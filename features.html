FC01 ACLR — Adjacent Channel Leakage Ratio Advanced click to expand +

3GPP §6.6.2 · test_Tx_ACLR · Cadence P0/P1/P2 · ETM 1.1 · frequency fm

Plain English First
Your PA amplifies the wanted signal but also creates distortion products that leak into neighboring channels. ACLR measures how much power you're spilling on your neighbors. Higher dB = less leakage = better. 3GPP minimum is 45 dB. PW internal target for Metro/FHGW is 55 dB.
Pass/Fail Limits
HardwareLimitToleranceBand Override
COMBA OPT7.2 / OPT8≥ 45 dB±0.8 dBNone
FHGW Box / Metro≥ 55 dB±0.8 dBb0407, b0307_2nd_run, b082028_2nd_run, b41_1st_run → 52 dB
MiniMetro≥ 55 dB±1 dBNone
How Test Runs
ETM: 1.1 only (QPSK 1/3 — cleanest signal, easiest for PA) · Frequency: fm (band middle) · EXA measurement: ACP mode → 4 offsets (A_lo, A_up, B_lo, B_up) → worst case is verdict
Note: B-offset (±2×BW) often hits instrument noise floor → use A-offset (±BW) for real verdict
What If It Fails
DPD not converged → check DPD alignment in PreChecks · PA compression → output power too high, reduce gain · DAC clipping → CFR input power wrong register (0x534020004) · Cable VSWR → reflection re-enters PA, creates mixing products
Interview Q
Q: ACLR is 50 dB but spec is 45 dB — why might it still fail? A: FHGW Box and Metro have a tighter internal spec of 55 dB. The 3GPP 45 dB limit is the regulatory minimum; PW adds 10 dB margin for interference management.

⑤ How pass/fail is decided
One function: LteUtils.limits_validation_aclr() in infrastructure/utils.py (L4956-5012). Higher ACLR is better, so the test fails when a measured ratio is ≤ the limit.
# threshold resolution order (first hit wins):
#  1) kpi_thresholds["test_Tx_ACLR"].min_limit + .tolerance   (+ band overrides)
#  2) tc_cadence["aclr_min_limit"], tolerance = 0.8
#  3) hard fallback: min_limit = 45, tolerance = 0.8   ("3GPP standard")
# -> this setup hits (1): min_limit = 55, tolerance = 0

aclr_pass_limit = aclr_min_limit - tolerance          # 55 - 0 = 55
for meas in measured:                                 # all 4 offsets, independently
    min_result  = FAIL if meas <= aclr_min_limit  else PASS
    pass_result = FAIL if meas <= aclr_pass_limit else PASS
return pass_results, aclr_pass_limit, min_results, aclr_min_limit
Key point: all four offsets are judged independently — the run fails if any one offset fails. There is no single "worst-case" number reduced before comparison; each ratio must be strictly > the limit. For this setup both the "min" and "pass" lines sit at 55 dB (tolerance 0).

3GPP §6.5.2 · test_Tx_EVM · Cadence P1 (via modulation_analysis) · ETM-dependent

Plain English First
EVM measures how far each IQ symbol lands from its ideal position on the constellation. Think of it as aiming accuracy — 0% is perfect, higher % = more scatter. 64QAM needs tighter clustering (≤3.5%) than QPSK (≤17.5%). Anything above limit = blocks decoded incorrectly.
EVM% Formula
EVM% = √(Σ|error_vector|² / Σ|ideal_vector|²) × 100
Error vector = difference between actual measured IQ point and ideal IQ point

EVM RMS vs Peak %
The frame-summary table carries two numbers: EVM (RMS, averaged over all subcarriers/symbols) and EVMPeak (the single worst RE). RMS is the pass metric (vs 3.5%); Peak is a diagnostic.
A high Peak/RMS ratio points to a sporadic impairment (one bad subcarrier, an LO spur, a DAC glitch) rather than uniform noise — if RMS is fine but Peak spikes, look for a localized defect, not a broadband SNR problem. Uniform thermal/quantization noise gives a low, steady Peak/RMS.
EVM Peak % vs RMS EVM — your early warning system
RMS EVM = root-mean-square over all symbols — the 3GPP/Metro pass metric (≤ 3.5%). EVM Peak = the worst single symbol, typically 3–5× RMS; not a BS limit, but the EXA reports it — use it for debug.
PatternMeaningLikely cause
Peak >> RMS (e.g. 2% / 15%)impulse distortion — occasional bad symbolsPA clipping on a PAPR spike, PLL phase hit, IQ-sample drop in eCPRI, B41 TDD trigger glitch
Peak ≈ RMS (e.g. 3% / 4%)uniform distortion — consistent impairmentIQ imbalance, LO leakage, DC offset, sustained phase noise, constant DPD error
Example: RMS 3.2% passes Metro's 3.5%, but Peak 14% reveals an intermittent fault — in the field it causes sporadic CRC failures + HARQ retransmits. Read both on the EXA: Modulation Analysis → Summary.
Q: EVM RMS 3.0% (passes) but Peak 18% — pass the test? Technically yes (spec is RMS-only), but 18% peak = one-in-N symbols severely wrong. Flag it and hunt the impulse source before sign-off: B41 TDD trigger timing, eCPRI sequence errors, the CFR register value.
Real RCT quirk — EVM modulation-table crash-guard (ECS)
table['EVM'] → table.get('EVM') (also ChannelPower, TimeOffset, FreqErr, RSTP). When the analyzer couldn't demod-sync, the modulation table came back missing those keys entirely → KeyError: 'EVM' hard-crashed the whole TX road-trip at the first frequency (seen on B8 real-tx). Now a no-sync read degrades to 0/fail (what the file's own _safe_float already intends) instead of crashing — the run completes and produces the full per-antenna/per-freq table. Behaviour is unchanged when the key is present.

FWK4 S-Plane Verification — PTP/SyncE timing tests (5G fronthaul) Framework click to expand +

The "S" = Synchronization · features/tech_5g/splane_verification_nr.py · docs SPLANE_AUTOMATION_EXPLANATION.md + knowledge_base/splane_verification.md

Plain English — what & why
In an O-RAN 7.2x split the RU must keep its clock aligned to the network using PTP (IEEE-1588) driven by a Grand Master (GM), backed by GNSS + internal oscillator. Get it wrong → TDD breaks, interference, 3GPP timing fails. Two headline metrics: Frequency Error (Hz / ppb) and Time Alignment Error / TAE (ns). The RU cycles PTP states LOCKED → HOLDOVER → ACQUIRING → LOCKED. Measured by a spectrum analyzer (RF freq/time via EVM table) and a Keysight oscilloscope (physical 1PPS / 10 MHz edge).
The three test types
Holdover — deliberately kill the reference (GNSS or PTP) so the RU free-runs on its oscillator, then measure drift. GM is forced to HOLDOVER before measuring so the whole window is genuine holdover. Variants: GNSS-loss, PTP-loss (C3 topology), two-GM redundancy (4 h scope capture).
Stability — long capture under PTP LOCKED to build statistics (~10 samples/s) + recovery tests (re-lock after PTP restart / full reboot, e.g. "locked in 145.2s").
Temperature monitoring — pre-test that waits for thermal equilibrium first, because oscillators drift with temp (TCXO ~±1 ppm/°C) and would contaminate results.
Config & pre-test flow
GMConfig caches the GM PTP settings (ptp_instance/ptp_port/gnss_port from setup.json "gm"). Cadence hierarchy Cadence-IDs["SPLANE"] → Group-IDs["TS_DL_SPLANE"] → Test-IDs; group carries PreTest[] + Tests[], dispatched via getattr(). Pre-test sequence: wipe FHGW logs → start PTP-packet tcpdump → temperature stabilize → PTP restart → start TX (aborts if all antennas < −20 dBm). PTP-restart polls fetch_lock_state() every 10 s until HOLDOVER, re-enables in a finally, then check_sync_state("LOCKED", timeout=600).
Concrete limits & durations
maxAbsTE < 1100 ns (3GPP, scope — abort on fail) · dTEh < 200 ns (holdover drift rate) · holdover KPIs freq_tolerance 50 ppb, time_offset 300 ns, max_time_error 1500 ns · non-holdover Freq_Error ±185 Hz, TAE 65 ns (±25), EVM 18.5%. Durations: temp stabilize 30 min (±2 °C), holdover/lock timeout 600 s, stability capture 1000 s, scope capture 4 h @ 200 ns/div. Typical "good": ±100 Hz, ±30 ns.

Why thermal noise is unavoidable

Thermal noise and the sensitivity floor:
Any resistive element above 0 K generates thermal noise. In your RX chain: the cable termination, the duplexer, the LNA input — all generate kTB noise. The LNA then amplifies both the incoming signal and all the noise it sees. You cannot eliminate this noise — you can only minimise the noise added after the signal enters the chain (which is what good LNA design does). This is why cryogenic receivers used in radio astronomy cool the LNA to near 0 K — it is the only way to get below the room-temperature kTB floor.
Noise voltage — how it appears on a spectrum analyser:
Noise voltage Vn = √(4kTBR). For a 50Ω system at 290K in 1MHz bandwidth: Vn = √(4 × 1.38e-23 × 290 × 1e6 × 50) = 0.895 μV = −107 dBm. On your EXA with preamp ON, this appears as the noise floor — the flat baseline across the span. When you inject a signal that rises above this floor, you can measure it. When the signal drops below it, it is lost in the noise.

Why Friis means you only need to care about the LNA

The Friis insight — one worked example:
Imagine you have a 7 dB NF mixer after your 20 dB gain LNA. Its Friis contribution is (F_mixer − 1) / G_LNA = (5.012 − 1) / 100 = 0.040 linear = 0.17 dB to system NF. Now replace that mixer with a perfect 0 dB NF mixer. System NF improvement = 0.17 dB. Barely measurable. But reduce cable loss before the LNA by 0.5 dB — system NF improves by exactly 0.5 dB, directly improving sensitivity by 0.5 dB. This is the Friis insight: optimise before the LNA, not after it.
In your lab: the pre-LNA components you can actually change:
The duplexer and pre-BPF are fixed inside the RFFE — you cannot change them. The LNA is a fixed chip — you cannot swap it. The only pre-LNA component you control in the test setup is the cable from EXM to the RU port. Shorter, lower-loss cable = better system NF in your measurement = better apparent sensitivity. This is why cable quality and measured loss matter, and why the VNA cable loss measurement is step 1 of every sensitivity test setup.

Why passive devices add noise equal to their loss

A resistor at room temperature generates thermal noise power = kTB. When a passive component like a cable attenuates a signal by X dB, it absorbs part of the signal power and replaces it with its own thermal noise. The result: the signal level drops by X dB but the noise floor drops by less (because the component adds its own noise). The net effect is exactly X dB of SNR degradation, which is the definition of X dB noise figure.

Why position relative to LNA is everything:
The Friis formula shows that each stage's NF contribution is divided by the gain of all preceding stages. A component before the LNA (G_preceding = 1 or less) adds its full NF. A component after the LNA (G_preceding = 100 for +20 dB LNA) adds only 1/100th of its NF to the system total. This is why the design rule is: minimise all loss before the LNA, and place the LNA as early in the chain as physically possible. Your duplexer and pre-BPF must be before the LNA for functional reasons (they select the band) but their loss directly degrades sensitivity.
Attenuator placement — the most common lab mistake:
When measuring TX power with EXA, you add a 30 dB attenuator to protect the EXA from the strong TX signal. This attenuator must go between the RU TX output and the EXA input — never between the signal source and the RU RX input. If you accidentally put the 30 dB pad in the RX path during a sensitivity test, you add 30 dB to system NF, and your measured sensitivity becomes 30 dB worse than reality. Always double-check the signal path before running any RX measurement.
Connector loss — the hidden NF contributor:
A single SMA connector in good condition has approximately 0.1–0.15 dB insertion loss. That is 0.1–0.15 dB of NF contribution if it is before the LNA. In a chain with 4 connectors before the LNA (source → cable → two adapters → RU port), that is 0.4–0.6 dB of additional NF from connectors alone. A damaged or incorrectly torqued connector can have 0.3–0.5 dB extra loss, immediately visible as sensitivity degradation. This is why the VNA connector inspection checklist exists and why torque specs matter for RF measurements.

The three noise types that matter most in your work

Of the five noise types, three are directly relevant to your daily testing. Thermal noise sets your sensitivity floor and is the subject of the entire DSA/NF calculation chain. Phase noise from the LO limits EVM and prevents high-order modulations from decoding. Quantisation noise from the ADC sets the dynamic range ceiling.

① Thermal noise — your sensitivity floor:
Generated by any resistive element at temperature above 0 K. Formula: P = kTB. In your RX chain, every lossy component (cable, duplexer, filter) generates thermal noise equal to its loss in power. The LNA amplifies both the signal and all the noise it sees, but its own added noise is small (NF = 2 dB). This is the noise the entire DSA framework is designed around — calculate it, characterise it per band, then test each band against its own correctly-adjusted threshold.
④ Phase noise — why it shows up in EVM failures:
The local oscillator (LO) that downconverts your RF signal to baseband is not a perfect single frequency — it has random phase jitter. This jitter appears as noise skirts around the carrier in the frequency domain. When the LO mixes with your signal, this phase jitter gets transferred to the baseband IQ constellation — the symbol points rotate slightly randomly, which increases EVM. Phase noise is why you see an EVM floor that does not improve even when SNR is excellent. For QPSK this is not a problem, but for 64QAM and 256QAM the tighter constellation margins make phase noise the limiting factor.
⑤ Quantisation noise — ADC dynamic range:
Every ADC rounds the analog signal to the nearest discrete level. With 12 bits, there are 4096 levels. The rounding error is the quantisation noise. SQNR = 6.02 × N + 1.76 = 6.02 × 12 + 1.76 = 74 dB. This means your ADC can cleanly handle signals up to 74 dB above the quantisation noise floor. If your signal swings too close to full scale (clipping), you get heavy distortion. If it is too weak (near the quantisation floor), you lose resolution. The VGA/AGC in your RX chain keeps the signal in the sweet spot — typically around −12 dBFS, well within the 74 dB dynamic range.

EXA DANL must be lower than RU sensitivity — always check:

In your test: EXM injects at sensitivity threshold (e.g. −97.5 dBm at RU port after cable). The PRACH detector inside the RU processes this. What is NF calibration?

NF cal answers one question: how much noise does your RX chain add to the signal? This is a hardware characterisation measurement — it tells you whether the LNA, duplexer, and cable are performing to spec. It does NOT write any correction value — it just confirms (or flags) the hardware quality.

Key terms, each explained

ENR — Excess Noise Ratio
The "how much hotter than room temperature is the noise source" spec. ENR=15 dB means the source outputs noise equivalent to a resistor at 290 × 10^(15/10) ≈ 9200 K when switched ON. This is the known reference your calculation depends on. The noise source module has its ENR printed on it and also stored in its EEPROM so the EXA can read it automatically.
Y-factor
Y = N_hot / N_cold in linear power. If hot output is −60 dBm and cold output is −66 dBm, the difference is 6 dB → Y = 10^(6/10) = 3.98. The Y-factor is how much "more noise" comes out when you switch the source hot vs cold. A low Y means the DUT is adding so much noise of its own that the source temperature barely matters — i.e., high NF device. A high Y means the DUT is quiet and is faithfully amplifying the difference — i.e., low NF device.
T_hot and T_cold
T_cold = 290 K (standard room temperature, the IEEE reference). T_hot = 290 × 10^(ENR/10). When the noise source is OFF, it still generates thermal noise at 290 K — that becomes your cold reference. This is why you use the same physical source for both measurements: it removes cable and connector uncertainty from the result.
NF formula: NF = ENR − 10·log(Y−1)
Where this comes from: NF definition is SNR_in/SNR_out. For a two-port device with gain G and noise temperature T_e, the output noise is G·k·(T_cold + T_e)·B for cold input and G·k·(T_hot + T_e)·B for hot input. Taking the ratio cancels G and B, and solving for T_e gives you NF = 10·log(1 + T_e/T_0). Substituting T_e from the Y-factor ratio gives the formula above.
In your lab — no standalone noise source needed
The EXA N9010B has a built-in NF measurement mode under Meas → Noise Figure. It drives its own internal noise source through Port 1 output, sweeps frequencies, and automatically computes NF vs frequency. You connect EXA Port 1 → RU RX port (via calibrated cable), tell it your cable loss, and it plots NF(f) for you. You then read off the NF at your band centre (e.g. 1950 MHz for B1 UL). The EXA handles the Y-factor math internally.
When NF is worse than spec — what to check
If measured NF > spec by more than 1 dB: (1) Check cable loss — every 0.1 dB extra cable loss before the LNA adds 0.1 dB to measured NF. (2) Check connector torque — loose SMA can add 0.3–0.5 dB. (3) Check LNA bias — wrong supply voltage shifts NF. (4) Check for LNA compression — if signal level too high, LNA is not in its linear region and NF appears worse. (5) Duplexer damage — a damaged duplexer filter adds extra loss before the LNA, directly adding to NF.

RX Gain Calibration — what ADC_ADJUST really is

The RX chain has many components between the antenna port and the ADC register: duplexer, BPF, LNA, VGA, mixer, another BPF, then the ADC. Each one has gain or loss. Rather than calibrating each component separately, RX gain cal treats the entire chain as a black box and finds one single number — ADC_ADJUST — that converts any dBFS reading into an accurate dBm reading at the RU input port.

ADC_ADJUST
A calibration constant stored in hardware.json, one per band per ADC channel. Formula: ADC_ADJUST = P_known_at_RU_port − dBFS_reading. Once calibrated, converting any future reading is: P_dBm = dBFS + ADC_ADJUST. It absorbs the total chain gain between RU port and ADC register — so even though the LNA adds +20 dB, the VGA might be at +6 dB, and the mixer has conversion loss of −7 dB, you never need to know each individual value. The single offset does it all.
Why separate ADC_ADJUST per band and per ADC channel
Each band has a different LNA gain and filter response, so the total chain gain is different per band. B1 at 2140 MHz has slightly different gain than B3 at 1843 MHz — even though they may share physical hardware, the frequency-dependent component behaviour means each band needs its own cal constant. Per ADC channel (B1 uses ADC channels 0/1/4/5, B3 uses 2/3/6/7) further accounts for ADC input impedance variation and any mismatch in the IQ paths.
Temperature dependence — why RSSI can drift
LNA gain changes with temperature — typically −0.02 to −0.05 dB/°C for GaAs pHEMT LNAs. In a hot lab (40°C vs 25°C calibration temp), the LNA gain drops ~0.3–0.7 dB, which makes RSSI read 0.3–0.7 dB low. If you see systematic RSSI error that grows as the RU warms up, this is why. Some RU designs have temperature compensation tables that auto-correct ADC_ADJUST as a function of measured board temperature — check hardware.json for a TEMP_COMP array.

TX Gain Calibration — what TX_GAIN register controls

The TX chain starts with the baseband IQ signal at full digital scale, passes through the DPD block, DAC, upconverter, PA driver, and finally the main PA. The total gain from baseband to RF output is roughly fixed by hardware, but there is always ±2–3 dB unit-to-unit variation from component tolerances. TX gain cal trims a digital attenuator (or the PA bias point) until the output power at the coupler port exactly hits the rated target.

tx_calibration_eeprom.json
This is the file that holds the final TX_GAIN register values after calibration — one per band per column (A/B/C/D). It is written during factory calibration and stored in the RU EEPROM. When the RU boots, it reads this file and loads the register values before enabling TX. If this file is missing or corrupt, the RU falls back to default gain values which can be 6 dB low or high — this is exactly what caused the ~6 dB B41 power deficit you found on unit 26050509 (fault 12: missing tx_calibration_eeprom.json).
Coupler ratio — the BOB SMA is not antenna power
The BOB SMA port is a directional coupler output, not the main antenna port. The coupler splits a small fraction of the TX power for monitoring — typically the coupling ratio is 30 dB, meaning the BOB SMA sees 30 dB less power than what goes to the antenna. So B1 rated power at BOB SMA = −16.7 dBm corresponds to +13.3 dBm at the antenna connector, or roughly 21 W EIRP per column after antenna gain. Always measure at the BOB SMA — connecting EXA directly to the antenna port would overload it instantly.
DPD and its interaction with gain cal
DPD (Digital Pre-Distortion) must converge before you measure TX power — it actively adjusts its coefficients for 30–60 seconds after power-on or after any power level change. If you measure output power while DPD is still adapting, you will see power fluctuating ±0.5 dB and possibly a wrong ACLR. Always wait for DPD to converge (check the DPD status register or simply wait 60 s) before taking a TX power or ACLR reading used for gain calibration.
Gain cal vs RSSI cal — how they relate
They are the same operation from opposite ends of the RX chain. RSSI cal (ADC_ADJUST) calibrates the entire RX path as one unit. NF cal measures just the noise-adding property of that path. TX gain cal calibrates the TX path. All three together ensure that when EXM injects −95 dBm, the RU reports −95 dBm via get_rssi, and when the BBU commands rated TX power, the antenna port outputs exactly rated power. Any mismatch between these three is a sign something has drifted or failed.

What sensitivity physically means

Sensitivity is the minimum signal power at the RU antenna port at which the receiver can still decode data at 5% BLER (3GPP threshold). It is not fixed — it depends on bandwidth, modulation, and band. The sensitivity formula is not an approximation — it is an exact derivation from thermal physics and information theory.

Sensitivity vs RSSI — the critical difference:
Sensitivity is a threshold — the floor below which decoding fails. RSSI is a measurement — the actual received power at any instant. During a sensitivity test you set EXM to exactly the sensitivity threshold and verify the RU can decode. In normal operation RSSI is whatever arrives — could be −70 dBm (UE nearby) or −105 dBm (UE at cell edge). Sensitivity defines where the floor is. RSSI tells you where you currently are relative to that floor.
Why bandwidth degrades sensitivity — the bucket analogy:
A wider channel (wider bandwidth) collects more thermal noise — like a wider bucket catches more rain. The signal power stays fixed but noise increases, so SNR worsens and you need a stronger signal to decode. 5 MHz sensitivity is 3 dB better than 10 MHz. 20 MHz is 3 dB worse than 10 MHz. This is why the DSA table has separate rows for each BW — same band, different thresholds.
BLER 5% — why this specific threshold:
3GPP defines sensitivity as the point where Block Error Rate = 5%. Below this, too many blocks fail and the system cannot sustain a call. At 5% BLER the link is just barely functional — this is the edge of coverage. The test is binary: inject at threshold power, count block errors, pass if BLER ≤ 5%. This is measured via the PRACH detection rate in your RCT — PRACH preamble either detected or not.

What is FRC and why it determines sensitivity

FRC (Fixed Reference Channel) is a 3GPP-defined test waveform with fixed modulation, coding rate, and resource allocation. Different FRCs test different capabilities. FRC A1 (QPSK 1/3) tests sensitivity because it gives the most robust link — maximum coverage, minimum signal requirement. The sensitivity number you compare against in your DSA table is always FRC A1.

Why QPSK 1/3 gives the best (lowest dBm) sensitivity:
QPSK has only 4 constellation points — they are spread far apart in the IQ plane. Even with heavy noise, the receiver can correctly decide which of the 4 quadrants the received symbol falls in. The 1/3 coding rate adds heavy redundancy — for every bit of data, 2 extra error-correction bits are sent. Together these give an effective SNR requirement of −1 dB, meaning the signal can be 1 dB below the thermal noise floor and still be decoded. This is why QPSK 1/3 gives the best sensitivity and is the standard for coverage-limited testing.

DSA — the complete story in one card

DSA stands for Dynamic Sensitivity Adjustment. It solves the problem of testing multiple bands with one test framework: each band has a different sensitivity because each band's hardware (LNA, duplexer, filter) has different noise figures. Rather than hardcoding different thresholds manually, DSA calculates a per-band offset from the sensitivity formula and instructs EXM to inject exactly the right power for each band automatically.

Step 1 — kTB: the physics floor
kTB = Boltzmann constant × Temperature × Bandwidth. At room temperature (290 K), in a 1 Hz bandwidth: kTB = 1.38×10⁻²³ × 290 × 1 = 4×10⁻²¹ W = −174 dBm/Hz. This is the absolute minimum noise any receiver can have — it cannot be beaten. For your 10 MHz channel: add 10·log(10,000,000) = +70 dB → noise floor = −104 dBm. For 5 MHz: +67 dB → −107 dBm. For 20 MHz: +73 dB → −101 dBm. Every 2× increase in bandwidth raises the noise floor by 3 dB.
Step 2 — System NF: what your hardware adds
Noise Figure is how many dB of extra noise your RX chain adds on top of kTB. Your chain (B1): cable 2.5 dB + duplexer 0.5 dB + pre-BPF 0.3 dB + LNA 2.0 dB + post-LNA components ≈0 dB = 5.75 dB system NF. The Friis formula shows that LNA dominates because everything after it gets divided by LNA's linear gain (×100). Everything before the LNA (cable, duplexer, BPF) adds its full loss as NF — this is why cable length matters enormously for sensitivity.

Per-band NF: B1=2.44 dB · B3=2.40 dB · B8=3.15 dB · B28=2.73 dB · B41=2.00 dB. B8 highest because 900 MHz LNA has higher noise, and the B8 duplexer has more loss at lower frequency. B41 lowest because TDD uses a T/R switch instead of a duplexer — less loss before the LNA.
Step 3 — Sensitivity: combining it all
Sensitivity = kTB_floor + 10·log(BW) + NF + SNR_required

SNR_required depends on modulation and coding rate. For FRC A1 (QPSK 1/3) — the standard sensitivity test — SNR_req = −1 dB. QPSK has only 4 constellation points spread far apart, so the receiver can decode it even when signal is 1 dB below the noise floor.

B1 worked example: −174 + 70 + 5.75 + (−1) = −99.25 dBm
B3 baseline: −174 + 70 + 5.71 + (−1) = −99.29 dBm (slightly better NF)
B8 worst: −174 + 70 + 6.46 + (−1) = −98.54 dBm (higher NF = worse sensitivity)
Step 4 — DSA offset: per-band correction
B3 is the reference baseline (DSA = 0). For every other band: DSA = Sensitivity_band − Sensitivity_B3. This gives the number of extra dB EXM must inject for that band to hit the correct threshold. The DSA values in your table (5 for B1, 8 for B8/B28) also include empirical corrections for path configuration differences (LB uses 2 RX paths vs HB 4 paths), flavour-specific gain settings, and actual measured hardware performance — not just the theoretical NF difference alone.
Step 5 — RX paths: what rev5/rev1/comb mean
Your AAU is 4T4R — 4 independent RX columns (A, B, C, D), each with its own LNA, cable, and ADC channel.

rev5 = Column A tested alone (single path, worst case for that column)
rev1 = Column B tested alone (independent verification of second chain)
comb rev3 = Columns A+B+C combined via MRC (Maximum Ratio Combining). MRC weights each chain by its SNR and sums them. Gain ≈ +3 to 4 dB over single path.
comb rev1 = All 4 columns A+B+C+D via MRC. Best possible. Gain ≈ +5 to 6 dB.

Why test single paths? Because MRC hides individual column failures. If Column C's LNA is dead, comb rev1 might still pass — A, B, D compensate. The rev5/rev1 single-path tests catch dead columns that combined results would mask. This is exactly what happened with AAU #510 — B1C and B1D showed dead in single-path but combined was degraded not zero.

MRC (Maximum Ratio Combining) does not simply add signals — it weights each chain by its own SNR quality before summing. A chain with strong, clean signal gets high weight. In practice chains are slightly unequal so you get +5 to 5.5 dB. For 2 paths (LB): +3 dB. For 3 paths: +4.8 dB.

The cable before LNA — your biggest variable in lab tests:
The 2.5 dB cable loss adds its full value to system NF because it comes before the LNA (no gain divides it). When you change cables, swap adapters, or use a different length cable between EXM and RU port, the system NF changes. Every 0.1 dB extra cable loss = 0.1 dB worse sensitivity = your test threshold moves by 0.1 dB. Always measure cable loss with VNA before any sensitivity test and subtract it from EXM output when calculating the power arriving at the RU port.
Why everything after the LNA is negligible:
LNA gain = +20 dB = ×100 linear. Post-BPF NF = 1.0 dB → linear 1.259. Its Friis contribution = (1.259−1)/100 = 0.0026 linear = 0.011 dB. Mixer NF = 7 dB → linear 5.012. Contribution = (5.012−1)/100 = 0.040 linear = 0.17 dB. These are completely insignificant compared to the 2.5 dB from the cable. This is why once the LNA is working correctly, improving anything after it gives virtually zero sensitivity improvement.
🎯 Analogy: the Friis formula is like a telephone game

Imagine passing a message (your signal) through a line of people. The first person in line can mishear the message and corrupt it — and everyone after will repeat the corrupted version louder. The second person can also mishear, but their error gets divided by how loudly the first person spoke (the LNA gain). By the time you get to the 10th person, their individual errors are completely drowned out by the first person's mistake. This is why the LNA (first active component) dominates the system NF — and why every millimetre of cable before the LNA directly costs you sensitivity.

What RSSI calibration actually is

RSSI calibration and RX gain calibration are the same procedure with different names. The goal is to find the single offset number — ADC_ADJUST — that converts any raw dBFS reading from the ADC into an accurate dBm power level at the RU antenna port. Once calibrated, P_dBm = dBFS_reading + ADC_ADJUST for any signal in that band.

The three numbers that must agree within 2 dB:

EXM output − cable loss = what arrives at the RU port (your reference, measured physically)
CLI get_rssi + ADC_ADJUST = what the RU's ADC chain reports (your calibrated reading)
DU testmac RSSI = what the baseband processing chain reports after FFT (another independent path)

All three must agree within ±2 dB. If EXM says −97.5 dBm, CLI should report −97.5 ± 2 dBm, and DU should also report −97.5 ± 2 dBm. If CLI is accurate but DU is off, the problem is in the FHGW/baseband path. If both CLI and DU are off from EXM, the ADC_ADJUST value is wrong.
Why separate ADC_ADJUST per band and per ADC channel:
B1 UL (1950 MHz) and B3 UL (1747 MHz) use different LNA gain settings, different filter responses, and different ADC input stages. Even if two ADC channels share the same physical ADC chip, the analog input path leading to each channel varies. Unit-to-unit component tolerance means the ADC_ADJUST for B1 on ADC channel 0 of unit 26050509 will differ slightly from the same channel on unit 26050508. This is precisely what RSSI cal measures and corrects — it is a per-unit, per-band, per-channel characterisation.
Common RSSI cal failures and root causes:
CLI reads 3 dB low → ADC_ADJUST was set with a different cable. Cable got swapped. Measure new cable loss with VNA and re-run cal.
CLI accurate but DU off by 2 dB → FHGW BFP decompression issue or testmac RSSI averaging window mismatch. Check FHGW firmware version.
RSSI drifts as unit warms up → LNA gain is temperature-sensitive. Re-run cal at operating temperature (after 30 min warm-up), or check if temperature compensation table (TEMP_COMP in hardware.json) is configured.
All bands off by same amount → EXM output power was wrong during cal. Re-verify EXM output with EXA before running cal.

The EXM must inject its UL signal only during SF2 and SF7 (the only full UL subframes in Config 2). The 9.9765 ms delay aligns the ARB waveform so it lands there. Special Subframe Config 6 (normal CP) decoded:
Total = 14 OFDM symbols per 1 ms subframe.
DwPTS = 9 symbols = 9 × 71.35 µs = 642.9 µs (DL pilot — RU transmits)
GP = 3 symbols = 3 × 71.35 µs = 214.1 µs (guard — silence for switching + propagation)
UpPTS = 2 symbols = 2 × 71.35 µs = 142.7 µs (UL pilot — narrow window)

The GP is only 214 µs. If the EXM injection is even 0.3 ms off, the UL burst clips into the guard period and the RU ignores it. For PRACH specifically — UpPTS is only 142.7 µs — a near-zero tolerance on timing alignment.
Why 9.9765 ms — the physics drops out exactly:
10.0000 ms   one LTE TDD frame (External 2 trigger period)
− 0.0203 ms   N_TA offset = 624 × Ts = 624 / 30,720,000 = 20.3 µs (3GPP TS 36.213 — mandatory UL timing advance for TDD)
− ~0.003 ms   cable length + Tx/Rx processing latency (~3 µs empirical)
──────────
= 9.9767 ms ≈ 9.9765 ms ✓   exactly matches your EXM screen
The 23.5 µs shortfall is not arbitrary. The N_TA advance ensures the UL burst's OFDM symbols (with cyclic prefix) land cleanly inside the RU's FFT capture window — arriving slightly early so the CP absorbs propagation uncertainty rather than clipping the GP→UpPTS boundary.
Two scenarios for the B41 sensitivity gap:

Scenario A — Delay toggle OFF (what the screenshot shows):
9.9765 ms value is configured but the toggle is OFF → delay not applied → injection is uncontrolled → most UL bursts land in DL subframes (SF3/SF4/SF5) → RU cannot receive them → BLER high → sensitivity appears ~5 dB worse than real. This is the cheap fix — just turn the toggle ON.

Scenario B — Delay ON but cable offset stale:
If your cable run differs from the ~3 µs assumed when the delay was calibrated, the fine offset is slightly wrong. Even a 0.2 ms error at the GP boundary causes partial burst loss. Test: with delay ON and fixed inject power (e.g. −97 dBm), sweep delay ±200 µs around 9.9765 ms in 20 µs steps — watch UL BLER. If BLER bottoms out at exactly 9.9765 ms: alignment is correct, the 5 dB is a real RX path issue. If BLER bottoms out at a different value: recalibrate the delay for your specific cable.
