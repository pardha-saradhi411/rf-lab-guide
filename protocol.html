PT01 MAC Layer — scheduling, HARQ, multiplexing: the traffic controller of the air interface Intermediate click to expand ▾
What MAC does — plain English
MAC (Medium Access Control) is the traffic police between the PHY layer and the RLC layer. It decides: which UE gets which resource blocks in this 1ms subframe, how much power, which MCS. Everything you measure in RCT (throughput, BLER, scheduling) is MAC's job.

MAC sits at Layer 2 — above PHY (Layer 1) and below RLC (Layer 2 also, higher sub-layer)

HARQRetransmission with soft combining — reuses failed packets to improve decodingBLER measurement in your sensitivity test
MultiplexingCombines data from multiple RLC bearers into one MAC PDUMultiple bearers = default+SRB+DRB in same transport block

HARQ deep dive — why BLER ≤ 5% is the sensitivity threshold
HARQ = Hybrid ARQ = combines Automatic Repeat reQuest with soft combining.

Process:
1. gNB sends transport block (TB) → UE decodes → if fail: sends NACK
2. gNB retransmits SAME data (chase combining) or incremental redundancy (IR)
3. UE soft-combines both attempts → higher chance of decoding
4. Max 4 HARQ rounds (LTE) → if still fail = BLER counted

Your sensitivity test measures BLER: at the sensitivity threshold, ~5% of TBs fail after all HARQ rounds. This is A1-3 FRC (QPSK 1/3 rate) — the minimum coding rate 3GPP defines for sensitivity.

8 HARQ processes in LTE: allows 8 TBs in flight simultaneously (pipelined). Round-trip delay = 8ms. B41 TDD has different HARQ timing due to slot structure.

Interview Q&A
Q: BLER is 20% at −65 dBm. The sensitivity limit is −68 dBm. What's happening?
A: At −65 dBm (3dB above the limit), BLER should be near 0%. 20% BLER at this power indicates: LNA degraded, cable fault, DSA mismatch, or HARQ is disabled/misconfigured. Check: sensitivity test at −50 dBm first — if BLER still fails, UL path is broken.
Q: What is NDI in the MAC header?
A: New Data Indicator — 1-bit toggle. Flips for a new TB. Stays same for HARQ retransmission. The receiver uses NDI to know: 'is this new data (start fresh combine buffer) or a retx (soft combine with previous)?'. Incorrect NDI = UE discards retx, can't combine = BLER jumps.
PT02 RLC Layer — TM/UM/AM modes: how data reliability is guaranteed above MAC Intermediate click to expand ▾
What RLC does — plain English
RLC (Radio Link Control) sits above MAC and below PDCP. It handles segmentation (big packets → small pieces that fit in one TTI) and reassembly (pieces → original packet). It also provides reliability (AM mode retransmits failed RLC PDUs).
Three RLC modes — when each is used
ModeFull nameError correctionUsed forVoLTE relevance
TMTransparent ModeNone — just passes dataBCCH, CCCH, PCCH (broadcast/paging)SIBs, paging messages
UMUnacknowledged ModeNo retx, but sequence numberedDTCH real-time (VoIP), MCCHVoLTE voice bearer — latency > reliability
AMAcknowledged ModeARQ retransmissionDTCH data bearersVoLTE IMS signaling SRB
AM mode ARQ — how it differs from HARQ
HARQ is at MAC layer — fast, hardware, 4 rounds, 8ms round trip.
RLC ARQ is at RLC layer — slower, software, many rounds, ~50ms round trip.

They work together: HARQ is the first line of defense (fast). If HARQ fails → MAC delivers corrupted TB to RLC → RLC AM detects via CRC → RLC ARQ retransmits → PDCP gets clean data eventually.

STATUS PDU: RLC AM receiver sends STATUS PDU listing which SNs were missing. Transmitter retransmits only those. Efficient — not retransmitting everything.
Segmentation and reassembly — why it matters for RCT
IP packet = up to 1500 bytes. One MAC TB at 10MHz QPSK = ~300 bytes.
RLC segments the IP packet across multiple TTIs → each gets an RLC PDU with SN.
Receiver reassembles when all segments received.

In your tests: FRC A1-3 (QPSK 1/3) sends one TB per TTI of fixed size. The RLC layer is essentially transparent in this test — MAC drives everything. RLC AM ARQ would only be visible in data throughput tests.
Interview Q&A
Q: VoLTE voice quality degrades but RTP stream shows no packet loss. What RLC mode is voice?
A: VoLTE voice uses RLC UM mode — no retransmission. Packet loss at RLC level directly becomes voice quality loss. The issue is at L1/L2 (BLER, HARQ), not RLC. Check: PDCP discard timer, HARQ BLER in that sector, and UL power control for the UE.
Q: Why does RLC exist if HARQ already handles retransmissions?
A: HARQ is limited to 4 rounds over 8ms — leaves residual BLER ~1%. For best-effort data (file download), 1% BLER over time compounds to significant loss. RLC AM ARQ handles the residual failures. HARQ = fast and hardware; RLC ARQ = reliable and software.

ROHC — why 60-byte headers matter for VoLTE
VoLTE RTP packet: 20 bytes payload (voice sample) + 12 RTP + 8 UDP + 20 IPv4 = 60 bytes overhead.
Without ROHC: 60-byte header + 20-byte data = 75% overhead → TERRIBLE efficiency
With ROHC: 3-4 byte header + 20-byte data = ~17% overhead → acceptable

ROHC works by: establishing context (first few packets send full header), then sending only fields that change (sequence number, timestamp). Static fields (IP addresses, ports) compressed to 0 bits after context established.

PDCP in EN-DC (LTE+NR dual connectivity)
In EN-DC, PDCP runs on the MN (Master Node = LTE eNB) for SRBs.
For DRBs (data): PDCP can split — send half the data over LTE and half over NR.
This is why PDCP has duplicate detection: same SN might arrive from both legs.

Handover during EN-DC: PDCP SN continuity maintained. UE doesn't need to retransmit from PDCP perspective — RLC handles retransmissions per leg.
Interview Q&A
Q: Why is integrity protection only for SRBs and not DRBs?
A: Adding 4-byte MAC-I to every user data packet would add significant overhead to high-speed DRBs (e.g., 100Mbps DRB = 50MB/s × 4 bytes = 200KB/s overhead, plus processing load). SRBs carry RRC/NAS signaling which must not be tampered with — the overhead is acceptable. User data integrity is protected at higher layers (TLS/HTTPS).
Q: PDCP sequence number wraps around. What happens?
A: 12-bit SN = 4096 values, 18-bit = 262144. The receiver handles wrap-around using a window. For 12-bit: window = 2^11 = 2048. As long as out-of-order doesn't exceed half the window, reassembly works. In 5G NR with 18-bit SN, wrap-around is much rarer.

Interview Q&A
Q: UE is stuck in RRC_CONNECTED but has no data throughput. Protocol layer issue?
A: Check: 1) DRB is established (RRCConnectionReconfiguration with DRB-ToAddMod). 2) Bearer is mapped to correct S1/NG tunnel (eNB-to-SGW/UPF). 3) UE sent RRCConnectionReconfigurationComplete. 4) Check PDCP ciphering mismatch — if UE and eNB use different keys, data silently dropped.
Q: What is SRB1 vs SRB2?
A: SRB1 (Signaling Radio Bearer 1): carries RRC messages AND NAS in RRC message container. Created FIRST in RRC setup — needed for all signaling. SRB2: carries NAS messages ONLY, more protected. Created after security activation. You cannot send NAS directly on SRB1 after SRB2 is set up.

NAS Security — why AKA matters for your testing
AKA (Authentication and Key Agreement):
1. MME/AMF gets auth vectors from HSS/UDM

Interview Q&A
Q: What is the difference between S1AP and NAS?
A: S1AP (S1 Application Protocol) is between eNB and MME — carries NAS as a transparent container plus S1AP procedures (bearer setup, handover, paging). NAS is end-to-end between UE and MME — eNB doesn't parse NAS, just forwards it. S1AP is per-eNB/per-UE context; NAS is per-UE/per-MME context.
Q: UE authentication keeps failing in lab. What do you check?
A: 1. SIM/USIM Ki matches what's programmed in HSS. 2. OPc vs OP — network uses one, SIM configured for other. 3. SQN (Sequence Number) out of sync — HSS SQN too far ahead of USIM counter. 4. Algorithm mismatch — UE supports MILENAGE but HSS using TUAK. 5. Check NAS logs: look for EMM Cause IE in Attach Reject.
PT06 HARQ — Hybrid ARQ: the retransmission mechanism behind your BLER measurements Advanced click to expand ▾
HARQ fundamentals — why hybrid?
ARQ (Automatic Repeat reQuest): if decode fails, send NACK, retransmit. Simple but wastes the failed attempt.
Hybrid ARQ: when decode fails, STORE the soft bits from the failed attempt. On retransmission, COMBINE soft bits → get better SNR effectively → decode from less power.

Two combining strategies:
• Chase Combining (CC): retransmit identical bits. Receiver combines. +3dB per retx.
• Incremental Redundancy (IR): retransmit different parity bits (higher code rate). Receiver combines all received versions → gets full mother code rate. More efficient than CC. LTE uses IR by default.

HARQ in TDD (B41) — variable timing
TDD HARQ timing depends on the UL/DL subframe configuration.
Not every subframe can carry feedback — only UL subframes.
Config 2 (DSUUD): DL subframes 0,1,5,6,7,8,9 → feedback in subframes 2,3

Impact on your testing: B41 HARQ process count and timing depends on tdd-config. If tdd-config in tc_cadence doesn't match BBU config → ACK/NACK timing mismatch → BLER appears worse than actual.
RV (Redundancy Version) sequence
LTE/NR uses 4 RVs: RV0 → RV2 → RV3 → RV1
RV0: systematic bits + first set of parity
RV2: different parity bits (adds new information for IR combining)
RV3: more parity
RV1: remaining parity

NDI (New Data Indicator): 1-bit toggle in DCI. Flip = new TB (reset soft buffer). Same = HARQ retransmission (accumulate soft buffer).
In your logs: look for ndi=0,rv=2 → retransmission in progress
BLER measurement — what it actually counts
BLER = Block Error Rate = (TBs failed after all HARQ rounds) / (total TBs sent)

Your sensitivity test uses FRC A1-3 (QPSK, R=1/3):
• At strong signal: BLER ≈ 0% — all TBs decoded on first attempt
• At sensitivity: BLER ≈ 5% — ~5% of TBs fail all 4 HARQ rounds
• Below sensitivity: BLER > 5% — UE cannot decode reliably

3GPP defines: A1-3 sensitivity = power where BLER ≤ 5% with 95% confidence
Interview Q&A
Q: BLER is 0% at your sensitivity test point. Is this a pass?
A: Check the power level. If BLER=0% AT the sensitivity limit power → PASS (better than spec). If 0% but you haven't decreased to the limit yet → keep decreasing power until BLER hits 5%, that's the actual sensitivity point. Your automated test does a 3-stage search specifically to find this point.
Q: What is HARQ process 0 vs process 7?
A: 8 HARQ processes run independently in parallel — like 8 separate ARQ instances. Process number identifies which soft combine buffer to use. Process 0's buffer is separate from process 7's. A TB arriving in subframe N uses the same process ID as its potential retransmission in N+8. If the IDs don't match → UE resets buffer → can't combine → BLER increases.
Reference Detail (ShareTechNote)
FDD HARQ: 8 processes. DL is asynchronous — the process ID + redundancy version are signalled in the PDCCH/DCI, so any process can be used in any order. UL is synchronous — the same process recurs every 8 subframes (ID inferred from timing). DL→UL feedback rides the PHICH (NACK → non-adaptive UL retransmission if no new DCI 0). RVs: adaptive (RV in DCI) or non-adaptive (predefined RV sequence, TS 36.321).
TDD HARQ timing is not the fixed n+4 of FDD — one UL subframe can acknowledge several DL subframes. Config 2 example: UL subframe 2 carries HARQ-ACK for DL subframes {4,5,6,8} of the previous frame plus 9. Bundling = any NACK in the set → retransmit all; multiplexing = retransmit only the NACKed ones (RRC-selected, affects PUCCH format). Special subframe = DwPTS / GP / UpPTS.

Reference Detail (ShareTechNote) — 5G NR HARQ
5G NR HARQ vs LTE: up to 16 processes (RRC-configurable, default 8) — more processes hide the longer round-trip at high SCS. Interview Q&A
Q: What is SUCI and why does 5G use it instead of sending IMSI in plaintext?
A: SUCI = Subscription Concealed Identifier. The IMSI (SUPI in 5G) is encrypted using the home network's public key before being sent over the air. Even if an attacker captures the Registration Request, they can't read the subscriber identity — only the home network (UDM/SIDF) can decrypt it. LTE sends IMSI in plaintext in the first Attach Request — a known privacy weakness.
Q: PDU session established but no IP connectivity. What do you check?
A: 1. UPF GTP-U tunnel: SMF sent PFCP Session Establishment to UPF? 2. gNB GTP endpoint correct in NGAP PDUSessionResourceSetupResponse? 3. DRB established on gNB and UE? 4. IP address assigned (check PDU Session Accept message for UE IP). 5. UPF routing: can UPF route to DN (Data Network)? 6. DNS: UE gets an IP but DNS fails?

Conditional Handover — 5G NR feature
Problem: Standard HO — command sent when condition met → UE must execute NOW. If radio deteriorates between command and execution → HO failure.

Conditional HO: gNB prepares multiple candidate cells. Sends a 'conditional HO command' with execution conditions:

UE stores the config and monitors. When conditions met → UE executes autonomously.

More robust in fast-fading environments. 5G NR Rel-16 feature.

Interview Q&A
Q: Your RCT passes all tests. But field team reports low throughput in that sector. What do you investigate?
A: Lab pass ≠ field pass. Check: 1) Cable losses different in field (longer cable runs). 2) Environmental factors (temperature → PA gain drift). 3) Interference from neighbouring operators (not present in lab). 4) Antenna tilt/azimuth (mechanical vs electrical). 5) Backhaul bandwidth bottleneck. 6) UE distribution — lab uses ideal UE, field has real UEs at various distances.
Q: What's the difference between pilot pollution and high interference?
A: Pilot pollution: many cells of similar strength — SINR is low because the reference signal from all cells adds as noise to each other. High interference: one or few dominant interferers at specific frequencies. Pilot pollution is a geometry problem (too many equal servers); interference is a frequency/power problem.

Intra- vs inter-frequency — why the measurement-gap detail matters
Intra-frequency: neighbour is on the same ARFCN → UE measures it continuously while receiving data (no gaps).
Inter-frequency / inter-RAT: UE must retune its receiver away from the serving carrier → the network configures measurement gaps (MGRP/MGL, e.g. 6ms every 40/80ms). During a gap no data is scheduled → small throughput cost.
Events: A1 (serving good — stop gaps), A2 (serving bad — start inter-freq/inter-RAT search), A3 (neighbour > serving + offset — the main HO trigger), A5 (serving < T1 AND neighbour > T2), B1/B2 (inter-RAT).

What problem CSFB solves
LTE/EPS is packet-only — there is no circuit-switched (CS) voice domain. Before VoLTE was widespread, operators used CSFB: when a voice call starts, the UE is moved out of LTE down to 3G/2G (the CS domain), the call runs there, and the UE returns to LTE afterwards. Needs the SGs interface (MME ↔ MSC) and a combined EPS/IMSI attach so the UE is registered in both PS and CS.

What SRVCC does
A VoLTE call is an IMS packet call on LTE. When the UE moves to the edge of LTE coverage, SRVCC hands the active voice call over to the CS domain (3G/2G) without dropping it. “Single radio” = the UE transmits on only one RAT at a time. Uses the Sv interface (MME ↔ MSC Server) plus IMS session transfer.

MSC Server → IMS/ATCF: Session Transfer (STN-SR) — media anchored

Interview Q&A
Q: What triggers SRVCC and which interface carries the PS-to-CS request?
A: A B2 measurement event (serving LTE below threshold-1 while the target UTRAN/GERAN cell is above threshold-2) makes the eNB send S1AP HandoverRequired with an SRVCC indication. The MME then uses the Sv interface to the MSC Server to request the PS-to-CS transfer, while IMS transfers the session (STN-SR) so the far end is unaffected.
Q: Why is eSRVCC better than basic SRVCC?
A: eSRVCC anchors the media at the ATCF/ATGW in the visited network, so at handover only the access leg is switched and the end-to-end media path barely changes — cutting the voice interruption from hundreds of ms to tens of ms.

Interview Q&A
Q: Why do most operators launch 5G SA with EPS Fallback instead of VoNR?
A: VoNR needs the whole chain — NR cell voice scheduling, UE support, IMS over NR, and good NR coverage/latency for a GBR flow — to be mature. EPS Fallback reuses the already-proven VoLTE/IMS stack on LTE, so operators guarantee reliable voice on day one and enable VoNR later as coverage and device support catch up.
Q: A 5G SA voice call takes ~2 s longer to connect than data. Why?
A: Almost certainly EPS Fallback: setting up the 5QI=1 flow triggers an inter-RAT move (handover or redirect) to LTE before the call completes, adding the RAT-change time. Confirm by checking for an NGAP handover / RRCRelease-with-redirect right after the IMS INVITE.

Interview Q&A
Q: Difference between RRC_IDLE and RRC_INACTIVE, and why did 5G add INACTIVE?
A: In IDLE the RAN has released the UE context, so resuming needs a full RRC setup plus NAS signalling and core paging over the whole tracking area. In INACTIVE the gNB retains the UE context and the NG connection is suspended, so the UE resumes with a lightweight RRCResume (I-RNTI) and RAN paging within the RNA. 5G added it because smartphones send frequent small bursts — INACTIVE gives near-idle battery with millisecond-scale resume, avoiding the signalling storm of constant IDLE↔CONNECTED transitions.
