NB01 Notes — 5G Overview, Numerology & Frame Structure Notes click to expand ▾
5G Overview nb1
  • 5G NR Release 15; Standalone & Non-standalone (NR cell uses LTE cell as anchor).
  • Use cases: eMBB, MCS (mission-critical), massive connected devices with low-latency, ultra-reliable; under & above 6 GHz.
  • Reference signals — 4 types: DMRS, SRS, CSI-RS, PTRS.
  • Channel mapping (logical → transport → physical):
  • Logical: PCCH, BCCH, CCCH, DCCH, DTCH.
  • Transport: PCH, BCH, DL-SCH, UL-SCH, PRACH.
  • Physical (DL): SS block (PSS, SSS, PBCH), CSI-RS; PDCCH (DMRS) = DL control; PDSCH (DMRS, PTRS) = DL data. Physical (UL): PUSCH (DMRS, PTRS) = UL control/data; PUCCH; PRACH, SRS = UL sync.
  • DMRS → PDSCH, PUSCH, PDCCH, PUCCH, PBCH. PTRS → PDSCH, PUSCH. SRS, CSI-RS.
  • CSI = Channel State Information: UE reports DL channel condition to gNB so it can do link adaptation, beamforming, spatial multiplexing. CSI includes CQI, PMI, RI.
Basic Information — Resource Block nb2
  • One NR RB = 12 subcarriers in freq domain (same as LTE).
  • SCS = 15, 30, 60, 120, 240 kHz → RB BW (×12) = 180, 360, 720, 1440, 2880 kHz (subcarrier BW).
  • Bandwidth: <6 GHz band → 100 MHz; >6 GHz band → 400 MHz.
  • μ table (Δf=2^μ×15 kHz): μ0=15kHz(26–275 RB, 6.32–49.5 MHz); μ1=30(26–275, 8.64–99); μ2=60(24–275, 17.28–198); μ3=120(24–275, 34.56–396); μ4=240(24–138, 69.12–397.44).
  • Channel BW (MHz) = RB count × 12 × SCS / 1000. Max RBs = Max channel BW / one-RB BW.
  • Supported BW / min guard band / max RB (N_RB): μ0 15kHz→50MHz, 692.5kHz guard, 270 RB; μ1 30→100MHz, 845kHz, 273 RB; μ2 60→100MHz, 1370kHz, 135 RB.
  • Guard Band (per side) = (channel BW − RBs×12×SCS)/2. Max RBs after guard = (supported BW − 2×guard)/(12×SCS).
Frame & Subframe / Slot / MCS nb3
  • 1 frame = 10 ms → 10 subframes = 1 ms each (subframe 0.5, indices 5–9 etc.).
  • OFDM symbols: 14 (Normal CP); 12 (Extended CP, μ=2 in FR1, SCS 60 kHz).
  • Slot differs by SCS. Slots per subframe: 15kHz=1, 30=2, 60=4, 120=8, 240=16.
  • Slot patterns (TS 38.213 v15.7): 56 patterns; 62–255 reserved; 255 if required.
  • MCS (Modulation and Coding Scheme): 1 symbol = RE. MCS = useful bits per RE.
  • Modulation bits/symbol: QPSK=2, 16QAM=4, 64QAM=6, 256QAM=8. Modulation order = 2^n.
  • 32 MCS indices (0–31); 29,30,31 reserved & used for retransmission.
  • Coding rate R = useful bits / total transmitted bits (useful + redundant/FEC) = n/(n+k).
Reference Signal Power / Frequency Bands / ARFCN nb4
  • Reference Signal Power = Max Tx Power − 10·log10(RB_cell × 12) (dBm).
  • Frequency bands (TS 38.104 §5.2): FR1 = 410 MHz – 7125 MHz; FR2 = 24250 MHz – 52600 MHz.
  • NR band types: FDD, TDD, SUL, SDL.
  • FR1: sub-6GHz; BW options 5,10,15,20,25,30,40,50,60,80,100; continuous range, high mobility; max BW 100 MHz; SCS 15/30/60 kHz; supports FDD/TDD/SUL/SDL.
  • FR2: mmWave; BW 50,100,200,400,800(CA); max BW 400 MHz; SCS 60/120/240 kHz; TDD only.
  • ARFCN = Absolute Radio Frequency Channel Number (2 for FDD DL/UL, 1 for TDD DL+UL).
  • Central freq: F = F_ref-offs + ΔF_global × (N_ref − N_ref-offs).
  • N_ref = N_ref-offs + (F_ref − F_ref-offs)/ΔF_global.
  • Table: 0–3000 MHz: ΔF 5kHz, F_offs 0, N_offs 0, N_ref 0–599999. 3000–24250: ΔF 15, F_offs 3000, N_offs 600000, 600000–2016666. 24250–100000: ΔF 60, F_offs 24250, N_offs 2016667, 2016667–3279167.
RE / BLER / PRACH formats / ZCZ nb5
  • RE (Resource Element) = smallest time-freq resource = 1 subcarrier × 1 OFDM symbol. 1 RB = 12 subcarriers × 14 OFDM = 168 REs.
  • BLER (Block Error Rate) = how often transport blocks fail CRC and need HARQ retransmission = (No. erroneous TBs)/(Total TBs sent).
  • PRACH formats: used in initial access, HO, UL sync. 2 groups:
  • Group A: short range (TDD), formats A1,A2,B,B2 etc., SCS 15/30 (Normal), short CP, faster access.
  • Group B: large cells (TDD), formats B3,B4 C0-C2, SCS 1.25/5 (Ext), long CP, more robust.
  • PRACH preamble format = sequence + cyclic prefix + guard time.
  • Zero Correlation Zone (ZCZ): how many UEs can use the same root sequence without colliding; controlled via RRC & SIB1.

NB02 Notes — Cell Search: SSB / PSS / SSS / PBCH / MIB Notes click to expand ▾
DCI (Downlink Control Information) nb7
  • Allocates physical resource for DL data (PDSCH) and UL data (PUSCH); controls power (UL power adjustment for PUSCH/PUCCH).
  • DCI carried in PDCCH; encoded PDCCH→CCE→REG, CRC masked with RNTI.
  • LTE DCI formats: 0=UL scheduling grant; 1=DL scheduling grant; 1A=DL scheduling (compact); 1B/1C/1D=special DL config; 2/2A/2B=MU-MIMO & spatial multiplexing; 3/3A=power control; 4=MU-MIMO DL & UL.
  • 5G DCI formats: 0_0, 0_1, 1_0, 1_1, 2_0–2_6, 3_0, 3_1.
  • RNTI/message mapping: MSG3 (between MSG4 & RRC setup complete) C-RNTI; MSG4/2 (between MSG3&4) C-RNTI; MSG2 (SIB, SI-RNTI); Msg1/RAR (between RACH & RAR) RA-RNTI.
  • Initial-access DCI usage: RAR=1_0, MSG2=1_0, MSG3=0_0, MSG4/MSG5=1_0/1_1.
  • DCI processing chain: DCI → CRC attachment (24 bits added?) → RNTI masking (16 CRC bits masked with RNTI) → interleaving → polar coding (encoded by polar) → rate matching → sub-block interleaving → scrambling (C-RNTI) → QPSK modulation → RE mapping → precoding. CCE indexing → CCE-REG mapping.
Cell Search nb7-8
  • Procedure by which a UE acquires time & frequency synchronization with a cell and detects the cell ID. Based on PSS, SSS, and PBCH DMRS located on the synchronization raster.
  • Steps: (i) UE tunes to specific frequency; (ii) selects the SSB and decodes PSS, SSS → 3+ bits (step (v)). To get the freq location of SSB we use the Synchronization raster.
SSB (Synchronization Signal Block) = PBCH block nb8
  • Components: Synchronization signal (PSS and SSS); PBCH + PBCH DMRS + PBCH data.
  • LTE vs 5G periodicity: LTE SS every 5 ms, PBCH every 10 ms; 5G SS+PBCH every 20 ms (2 NR frames) default.
  • SSBs transmitted in a batch forming an SSB Burst (one SSB per beam). Beam sweeping = mechanism UE uses to measure & identify the best beam. Collection of SSB bursts = SSB Burst Set.
  • Max no. of SSBs is frequency dependent: 4 (below 3 GHz), 8 (3–6 GHz), 64 (6–52.6 GHz) — in one group. Always-on transmission is reduced (vs LTE).
  • Each SSB has a unique number = SSB index. SSB occupies 20 subcarriers (20 RBs?), given 0–239. After scanning each SSB beam, measures RSRP/RSRQ/SINR; whichever is good it decodes PSS/SSS/PBCH on that.
  • PSS (Primary Sync Signal) N_ID^(2): physical-layer signal, helps UE get radio frame boundary; m-sequence (special LFSR); 127 values, subcarriers 56–182 (127 subcarriers); placed at first OFDM symbol; position of 1st symbol in radio frame; DL frame sync. d(n)=1−2x(m), m=(n+43·N_ID^(2)) mod 127, 0≤n<127, N_ID^(2)∈{0,1,2}.
SSS + PCI nb9
  • SSS (Secondary Sync Signal) N_ID^(1): helps UE get subframe boundary; 127 values, subcarriers 56–182; 3rd OFDM symbol (symbol 2), position of 1st symbol in subframe; m-sequence; DL frame sync.
  • d(n)=[1−2x0((n+m0) mod 127)]·[1−2x1((n+m1) mod 127)]; m0=15·⌊N_ID^(1)/112⌋+5·N_ID^(2); m1=N_ID^(1) mod 112; N_ID^(1)∈{0..335}.
  • PCI (Physical Cell ID) = 3·N_ID^(1) + N_ID^(2); SSS gives 0–335, PSS gives 0–2. Max = 3·335+2 = 1007 → total 1008 PCIs (NR). (LTE = 504.)
  • PBCH DMRS: physical-layer reference signal used for decoding PBCH. In LTE there was CRS; in 5G removed to reduce overhead → dedicated DMRS for PBCH decoding.
PBCH DMRS placement + MIB nb10
  • PBCH DMRS used in subcarriers 0–239 in 2nd & 4th OFDM symbol, and 0–47 + 192–239 in 3rd OFDM symbol.
  • MIB (Master Information Block): transmitted over BCH transport channel and PBCH physical channel; QPSK modulated; includes info to decode SIB1; periodicity 80 ms.
  • MIB contents: systemFrameNumber (10 bit → 6 MSB in MIB, 4 LSB in PBCH); subCarrierSpacingCommon (SCS); ssb-SubcarrierOffset (finds location of SSB — position of SSB in freq domain, distance of SSB from point A); pdcch-configSIB1 { controlResourceSetZero (CORESET#0, 0–15) → locate & monitor PDCCH; searchSpaceZero (0–15) → find DCI 1_0 which tells about SIB1 location → decode SIB1 }; cellBarred (barred/unbarred); intraFreqReselection (allowed/not allowed).
PDCCH (Physical Downlink Control Channel) nb11
  • Carries DCI (scheduling info for PDSCH/PUSCH, UL power control, slot format, which PRB/OFDM symbols not mapped, etc.).
  • Two aspects: transmitting control info = CORESET; how UE obtains control info in CORESET.
  • CORESET#0: monitor CORESET at a designated monitoring occasion; implemented by blind detection (blind decoding) in the candidate set in the configured search space.
  • CORESET basic unit = REG (Resource Element Group) = a group of 12 consecutive REs in the same OFDM symbol within a resource block. Total REGs = 6·N_RB × 12 subcarrier / (4 REs per REG) × N_OFDM symbols.
  • PDCCH basic unit = CCE (Control Channel Element) = basic scheduling unit carrying DCI on PDCCH; 1 CCE = 6 REGs; DCI occupies 1, 2, 4, 8 or 16 CCEs (aggregation level).
  • Search space set → PDCCH candidate → CCE → CCE-REG mapping → REG → CORESET.
  • PDCCH 3 types: (i) Common PDCCH; (ii) Group Common; (iii) UE-specific.

SIB1 nb12
  • SIB1 transmitted over DL-SCH; cell-specific (valid only for serving cell).
  • Minimum System Information = MIB + SIB1 (RMSI = Remaining Minimum SI). Other System Information (OSI) = SIB2…SIB9.
  • Channel mapping: BCCH (logical) → BCH & DL-SCH (transport) → PBCH & PDSCH (physical).
  • Periodicity 160 ms; uses DCI 1_0 for SIB1 PDSCH resources.
  • O-RAN: DU generates content of MIB & SIB1; DU→CU→UE via F1AP.
  • SIB1 contents: cell selection info (q-RxLevMin, q-RxLevMinSUL, q-QualMin); cell access related (PLMN, tracking area code, cellIdentity, cellReserved); si-scheduling info; serving-cell common config; other SIBs; si-window size; pdcch-configCommon, pdsch-configCommon, IMS emergency support flag; UE timers & constants (t300/t301/t310, n310/n311 for managing RRC connection); UAC barring info; ConnEstFailControl.
UE timers & constants; Serving-cell common config; SI scheduling nb13
  • Timers: T300 (1000ms) starts when UE sends RRC connection req; if expires before RRC setup, UE retries RA. T301 starts on RRC reestablishment req; no response → idle. T310/T304 start after link failure; if expired → RRC re-establishment. T311 after RRC failure; if expired → idle. T319 used entering RRC-INACTIVE (resume req). N310 = no. consecutive out-of-sync before triggering T310. N311 = no. consecutive in-sync to stop T310 & cancel recovery. T3512/T3502 (min) when UE enters RRC-IDLE/INACTIVE.
  • Serving-cell common config: (i) DownlinkConfigCommon (freqBandIndicator, SCS, BW, PDSCH config = time-domain resource allocation for data, PDCCH config = CORESET/searchspace/SIB1 searchspace/RA space, initial DL BWP); (ii) UplinkConfigCommon (freqBandIndicator, SCS, BW, initial UL BWP, rach-configCommon for RA, pusch-config/pucch-config define UL channel behaviour); (iii) PCCH config (paging info); (iv) BCCH config (MIB/PBCH params); (v) SSB-config (ssb-positionInBurst & ssb-periodicityServingCell).
  • SI scheduling info: si-broadcastStatus (broadcasting); si-periodicity (rf8, rf16, rf32, rf64, rf128, rf256 radio frames; e.g. rf128 = 128×10ms = 1.28 sec).
sib-mapping + CELL SELECTION CRITERIA nb14
  • sib-mappingInfo: type of SIB; valueTag (identify/help UE re-read SIB content); areaScope (whether scheduling applies to entire tracking area or cell level); si-windowLength (ms/sec) — UE monitors PDCCH in this window for a DCI pointing to the PDSCH containing the SIB(s).
  • Cell Selection Criteria — 3 criteria: Signal strength/Quality; PLMN selection; Service type.
  • Signal quality: UE won't register even if it detected the cell and decoded SIB/MIB unless Srxlev>0 AND Squal>0 (if not met → no MSG1).
  • Srxlev (dB) = Q_rxlevmeas (RSRP) − (Q_rxlevmin (dBm, min RSRP) + Q_rxlevminoffset) − P_compensation − Q_offsettemp.
  • Squal (dB) = Q_qualmeas (RSRQ) − (Q_qualmin (dB, min RSRQ) + Q_qualminoffset) − Q_offsettemp.
  • All parameters from SIB1.
  • Acceptable cell: not enough to be suitable but meets minimum to make an emergency call — cell not barred; cell selection criteria met.
Suitable cell + CBG nb15
  • Suitable cell: UE may camp for normal service — selected PLMN / registered PLMN / equivalent PLMN; cell not barred; cell is part of at least one TA not in the "forbidden tracking area for roaming"; meets cell selection criteria.
  • Cell selection types: initial, stored, reselection.
  • CBG (Code Block Group): configured via RRC (RRCSetup/RRCReconfig); manages data transmission over PDSCH. A Transport Block (TB) is divided into smaller Code Blocks (CB); a group of CBs = CBG. Enables efficient retransmission — instead of resending the whole TB, only the failed CB(s). DCI format 0_1/1_1. Each CB individually appended with a CRC to detect errors.
Transport Block + Uplink Sync (RACH MSG1) nb16
  • Transport Block: basic unit of data exchanged between higher layer and physical layer; the payload that is encoded, modulated and transmitted over the air; mapped to PDSCH in DL, PUSCH in UL.
  • Uplink Synchronization — RACH (Random Access Channel): UE sends RACH preamble (rach info from SIB1), creates one RAPID, sends to gNB, starts T300. Initial access = DL sync + RACH.
  • MSG1 (preamble transmission): UE selects a random access preamble from a predefined set (~64 preambles total; formats A1,A2,B1–B4,C0,C2; types 0,1,2,3; short & long); selects a random sequence number; transmits preamble + sequence on PRACH. Purpose: achieve UL sync between UE & gNB; obtain resources for MSG3. Criteria: sync should happen only when necessary and only to one UE.
When RACH / RA-RNTI / RAR / MSG3 nb17
  • When RACH: initial access from RRC-IDLE; RRC connection re-establishment; HO; transition from RRC-INACTIVE; SCell addition; request for other SI; beam failure recovery.
  • Types: Contention Based (CBRA) → resolved via contention resolution; Contention Free (CFRA).
  • RA-RNTI = 1 + s_id + 14×t_id + 14×80×f_id + 14×80×8×ul_carrier_id (range 1–17920). s_id = index of first OFDM symbol of specified RACH (0≤s_id<14); t_id = index of first slot of PRACH in system frame (0≤t_id<80); f_id = index of PRACH in freq domain (0≤f_id<8); ul_carrier_id = UL carrier used for msg1 tx (0,1).
  • RAR (Random Access Response) = MSG2: after preamble, UE listens PDCCH (DCI 1_0) scrambled with RA-RNTI within the RAR-window (rar-windowLength IE in SIB). RAPID in RACH and RAR must be same. RAR contains RA-RNTI, MAC transport block, timing advance, uplink grant, TC-RNTI. 16-bit identifier (0x0001–0xFFFE; 0x0000 & 0xFFFF reserved).
  • RRC Setup Request = MSG3: includes ue-identity and establishment cause; ue-identity can be a random number range 0–(2^39−1); sent on UL grant provided by gNB in MSG2, over SRB0 and UL-CCCH.

Initial Call Flow (UE ↔ gNB ↔ AMF) [path UE→gNB-DU→gNB-CU-CP→gNB-CU-UP→AMF] nb18
  • DL-sync: MIB, SIB (gNB→UE).
  • UL-sync (SRB0): RACH (msg1) → RAR (msg2) → RRC setup req (msg3, ue-id 0–2^39−1) → RRC setup (msg4).
  • SRB1: RRC setup complete + NAS Registration → gNB sends NGAP: Initial UE message + registration req → AMF.
  • Identity: NGAP NAS identity req → UE; UE → identity response → AMF.
  • Authentication (AUSF 5G-AKA / UDM SUPI & subscription): Auth req (to UE) → Auth response (16 bits) → AMF.
  • NAS Security Mode: NAS security mode command → Security mode complete.
  • gNB: Initial context setup req + registration accept.
  • UE capability exchange: UE capability enquiry → UE capability info → AMF.
  • AS SMC: AS security mode command → AS security mode complete.
  • RRC reconfig + SRB2, DRB + Registration Accept → RRC reconfiguration complete → Initial context setup response.
  • Registration complete → AMF.
  • PDU: PDU session establishment request → gNB PDU req → AMF → SMF → UPF (create GTP-U tunnel, PDU with UPF) → PDU response → UE.
  • ue-identity range: LTE 0–2^32−1; 5G 0–2^39−1.
RRC Setup + RRC Setup Complete / Registration Request / Identity transfer nb19
  • RRC Setup: sent on SRB1; carries contention resolution and master cell configuration; UE stops T300 on receiving it; info used to access network.
  • Interview: RRC Setup configures the entire MAC-RLC-PHY stack for the UE after initial access — assigns SRB1, configures initial UL/DL BWPs, sets up PUCCH & PUSCH channels, defines control regions via PDCCH config. Moves UE to RRC-CONNECTED, prepares for data/NAS signalling.
  • Contains: radioBearerConfig, masterCellGroup (MAC, RLC, PHY), PDSCH, PDCCH, PUSCH, PUCCH, tag-ID, spCellConfig.
  • RRC Setup Complete + Registration Request: RRC setup complete contains selected PLMN, registered AMF, dedicated NAS message. NAS Registration Request toward AMF in the Initial UE message.
  • gNB selects AMF and creates RAN UE NGAP ID for the UE; AMF uses this ID to address UE context to gNB.
  • Initial UE message contains: RAN UE NGAP ID, NAS info, user location information, RRC establishment cause, UE context request.
  • Identity transfer: if there is a change in last AMF selected by gNB and SUCI is not provided by UE nor retrieved from old AMF, the Identity Request procedure is initiated by AMF sending an identity request to the UE requesting the SUCI. UE derives SUCI using the provisioned public key of the PLMN.
SIM identities (Table 2 part 1) nb20
  • SUPI (Subscription Permanent Identifier): 15 or 16 digits, format MCC(3)/MNC(2-3)/MSIN(up to 10); like IMSI (e.g. 001010101234); never sent in plain text; generated by USIM (UE); used in authentication, registration.
  • SUCI (Subscription Concealed Identifier): encrypted version of SUPI using public key of the HPLMN; contains Home Network Public Key, protection scheme, SUPI; generated by UE (before sending); used in Registration Request (NAS).
  • 5G-GUTI (5G Globally Unique Temporary Identity): temporary UE identity. Structure = PLMN-ID (MCC+MNC) + AMF region ID + AMF Set ID + AMF pointer + TMSI → 80 bits. Generated by AMF; used as temporary UE identity. (GUAMI + TMSI = GUTI.)
  • GUAMI (Globally Unique AMF Identifier): PLMN-ID + AMF region ID + AMF Set ID + AMF pointer; unique across AMFs; generated by AMF; used for AMF internal tracking (not sent over the air).
SIM identities (Table 2 part 2) + Authentication/AKA nb21
  • GUAMI (48 bits): identifies which AMF is serving the UE; generated by network (AMF).
  • TMSI (32 bits): 32-bit random number (part of GUTI); generated by AMF; temporary mobile identity to avoid sending SUPI.
  • GUPI (Globally Unique Permanent Identifier): refers to SUPI (permanent subscriber ID, globally unique); generated by UE (stored in USIM); used internally for mapping subscription.
  • IMEI: 15-digit numeric = TAC(8 digits) + SNR(6) + check digit(1); generated by UE hardware; used for equipment identity checks.
  • IMEISV: 16 digits = IMEI(14 digits) + SV(2 digits); UE hardware; used for device compliance/blacklist.
  • KSI-ASME: key set identifier for ASME; 3-bit value (range 0–7) typically shown in hex; generated by AMF; used to identify the NAS security context b/w UE & AMF.
  • Authentication req/response (T3560 start, stop): core network performs authentication so UE is legitimate & legally authorized to get service. Also called AKA (Authentication and Key Agreement) — mutual authentication b/w user & network, derives crypto keys to protect U-plane & C-plane.
  • 3 scenarios: Normal authentication (completes successfully); Authentication reject (network denies); Registration reject (UE denies registration).
  • Authentication response contains: auth code, sequence number, response parameter — crucial for validating UE identity in core; length 16.
AKA message flow + Security Mode Command nb22
  • Flow: UE → AMF/SEAF (registration req, SUCI) → AUSF (authent req) → UDM/ARPF/SIDF (auth req): SUCI-to-SUPI de-conceal, 5G-AKA select, generate authentication vector.
  • Back: auth response ← auth res ← AMF sends auth request to UE (RAND, AUTN, ngKSI).
  • UE → auth response (RES*) → AMF; AMF verifies (Verify RES* with XRES*), converts K_AUSF → K_SEAF.
  • (For parameters, refer AKA parameter — 2 pages away.)
  • Security Mode Command / Complete: establishes integrity & ciphering algorithms for NAS and RRC layers.
  • Security mode command contains: selected NAS Integrity Algorithms, selected NAS Ciphering Algorithms, replay protection parameters, KSI-ASME.
  • UE responds/confirms it has successfully set up ciphering & integrity protection.
  • Types: Integrity (IA) → protects signalling msg; Ciphering (EA) → encrypts data. UE sends all Integrity & Ciphering list it supports; AMF selects and sends in security mode command; UE accepts in security mode complete.
  • NEA → NEA0, NEA1, NEA2, NEA3; NIA → NIA0, NIA1, NIA2, NIA3 (NEA0/NIA0 = no protection/null).
Security algorithms + Initial Context Setup Req + AS security nb23
  • Algorithm table:
  • SNOW3G: LTE&5G (NIA1/NEA1); stream cipher; encryption & integrity; lightweight, good for legacy; used in NAS, RRC, UP.
  • AES-128: LTE&5G (NIA2/NEA2); block cipher; encryption, MAC; high security, widely used; NAS, RRC, UP.
  • ZUC: 5G only (NEA3/NIA3); stream cipher; encryption & integrity; low latency, used in China; NAS, RRC, UP.
  • Initial Context Setup Req: AMF allocates "AMF UE NGAP ID" so gNB uses this to address UE context on AMF. Also contains RRC registration accept. Contains GUAMI, S-NSSAI (Single Network Slice Selection Assistance Info — used by UE & network to identify/select a specific 5G network slice during registration & PDU), security info.
  • AS UE capability & AS security: gNB enquires UE capability (UE capability enquiry & info); after receiving, gNB updates capability to AMF. Contains supported band list, band combinations, 256QAM support, CA support, measurement & mobility parameters. gNB sends AS security mode command to UE to start integrity protection & encryption; then downstream data flows.
RRC Reconfiguration + Registration Accept nb24
  • After AS security, UE derives keys per the integrity/encryption algorithm in the security mode message, replies security mode complete; upstream encryption starts.
  • RRC Reconfiguration: gNB issues RRC reconfiguration to establish SRB2 and DRB. After SRB2 & DRB established, UE replies RRC reconfiguration complete. gNB signals successful DRB setup with INITIAL CONTEXT SETUP RESPONSE to AMF.
  • Contains: srb-ToAddModList (SRB2), drb-ToAddModList (drb-info), measConfig (measObjectToAddModList — measObject for n no. of freq; reportConfigToAddModList — reportConfig A2/A3/A4; measIdToAddModList — measId for reportConfig), masterCellGroup (RLC, MAC), spCellConfig (special/primary cell group).
  • Registration Accept: provides UE with all network-approved parameters for ongoing 5G service (identity, tracking area, slices, timers). Timers like T3512, T3502 define how often & when UE must re-register or retry.
Registration timers + PDU Session Establishment + Measurement report nb25
  • T3512 controls how often the UE performs a periodic registration update to remain known to the network. T3502 tells the UE how long it can stay idle before being implicitly deregistered. Both NAS timers; T3512 configured in SIB1, T3502 delivered via Registration Accept.
  • PDU Session Establishment (T3583, T3582): a PDU session provides UE connectivity to a data network (DN), enabling data services; managed by SMF, involves UPF.
  • UE sends NGAP (UL NAS Transport) message. UE → AMF (PDU session ID, PTI, PDU session type, ssc mode, DNN, S-NSSAI, req type, SGSN capability, extended protocol config options).
  • AMF → SMF (to create session context); SMF → PCF/UDM/UPF (subscription data, policy rules, user-plane resources).

PTI / TEID / TTI nb31
  • PTI (Procedure Transaction Identity): a UE-assigned ID to track NAS SM procedures like PDU session request; distinguishes multiple concurrent session req/response (like tabs); included in NAS SM messages (PDU session request, release, etc.); NAS layer (5G only), sent UE→AMF, passed to SMF; UE assigns unique PTI (0–255), SMF includes it in all related msgs.

SDAP / PDCP / RLC / MAC nb37
  • SDAP (Service Data Adaptation Protocol): QoS-flow-to-DRB mapping — reflective mapping (DL DRB used for UL as well) or explicit config (separate for UL). Functions: mapping b/w a QoS Flow and DRB; marking QoS flow ID (QFI) in both UL & DL packets; a single SDAP entity is configured per PDU session, except for DC where two entities can be configured.
  • PDCP (Packet Data Convergence Protocol): sequence numbering; header compression/decompression; transfer of user data; reordering & duplicate detection; ciphering & deciphering & integrity protection; duplication of PDCP PDUs. (Notes: PDCP out-of-order deciphering drawback in LTE; RLC Rx window operation in NR; duplication of PDCP PDUs.)
  • RLC (Radio Link Control): transfer of upper-layer PDUs; error correction through ARQ; segmentation & re-segmentation; reassembly of SDU; RLC re-establishment. (Note: no concatenation and no reordering in NR RLC.) URLLC latency 0.5ms UL&DL, eMBB 4ms UL&DL. Modes: TM/UM/AM.
  • MAC (Medium Access Control): mapping b/w logical & transport channels; multiplexing/demultiplexing of MAC SDUs belonging to one or different logical channels into/from TB delivered to/from PHY on transport channels.
MAC (cont.) + PHY + Header Compression nb38
  • MAC: scheduling information reporting; error correction through HARQ; priority handling b/w UEs by dynamic scheduling; priority handling b/w logical channels of one UE via logical channel prioritization & padding; a single MAC entity can support one or multiple TTI durations; logical channel prioritization controls which TTI duration a logical channel can use.
  • PHY (Physical layer) functions (radial map): MIMO, Time sync, Beam management, channelization, Frame structure, Power control, CSI report, Freq sync.
  • Header Compression: reduces IP/TCP/UDP header overhead (40–60 bytes to 1–3 bytes) using ROHC (Robust Header Compression); saves BW, increases efficiency esp. in VoNR, gaming & small-packet traffic; sent on RRC connection setup/Reconfig; occurs at PDCP on DL & UL; compression applied by PDCP at sender & decompression at receiver; both must negotiate ROHC profile & context during bearer setup; used on DRBs.
Paging + Transmission Modes (intro) nb39
  • Paging: mechanism used by the network to notify a UE in IDLE or INACTIVE state that it has DL data or signalling pending; avoids keeping UE always-ON; used when UE is in RRC-IDLE or RRC-INACTIVE (5G only) and the network needs to reach it; sent via PDSCH after DCI scheduling over PDCCH within paging occasions; AMF/gNB uses TMSI (4G) or GUTI (5G) to address UE; UE monitors paging frames based on DRX cycle and UE-ID hash. Two types: CN-triggered by AMF (for NAS message); RAN-triggered by gNB (due to RLF recovery).
  • TM (Transmission Modes): defines how the eNB (4G) or gNB (5G) transmits data to the UE, particularly for MIMO & beamforming. In LTE, TMs are explicitly numbered (TM1–TM10) and configured via RRC Connection Reconfiguration. In 5G, TMs are replaced by dynamic transmission schemes using CSI feedback — there's no fixed TM numbering.

NR logical channels list nb43
  • BCCH (Broadcast Control Channel): transmits system information from network to UEs in a cell; UE acquires SI before accessing. Used in SA in NR; in NSA, SI provided by LTE cell, no BCCH.
  • PCCH (Paging Control Channel): pages UEs whose location at cell level is unknown; paging msg transmitted in multiple cells. Used in SA; in NSA, paging provided by LTE.
  • CCCH (Common Control Channel): transmits control info to UEs w.r.t. random access.
  • DCCH (Dedicated Control Channel): transmission of control info to/from a UE; used for individual UE configuration (setting parameters at different layers).
  • DTCH (Dedicated Traffic Channel): transmission of user data to/from a UE; the logical channel used for all unicast UL & DL user data.
NR transport channels nb44
  • Transport channel: defined by how and with what characteristics information is transmitted over the radio interface. PHY offers MAC services as transport channels. Data organized in Transport Blocks (TBs).
  • BCH (Broadcast Channel): transmits BCCH system info, specifically MIB; fixed transport format from spec.
  • PCH (Paging Channel): transmission of paging info from PCCH logical channel; supports DRX so device saves battery by waking only at predefined instants.
  • DL-SCH (Downlink Shared Channel): main DL transport channel; supports dynamic rate adaptation, channel-aware scheduling, HARQ, spatial multiplexing. Also carries some BCCH SI not mapped to BCH. Each device has a DL-SCH per connected cell (+1 additional for SI slots).
  • UL-SCH (Uplink Shared Channel): UL counterpart to DL-SCH for UL data transmission.
  • RACH (Random Access Channel): a transport channel, though it does not carry transport blocks.

Xn Handover nb53
  • Xn Handover is similar to X2 in LTE. Prerequisite: an Xn interface must be up b/w source and target gNB.
  • Only applicable for "Intra-AMF mobility"; Xn HO can't be used if source & target gNB are with different AMF.
  • Xn HO can be intra or inter frequency. UPF can be different for source & target gNB. Re-registration required if source & target gNB belong to different TAC.
  • Xn HO is faster than NG as it has a "short signalling path" and 5G core is involved only to switch the PDU session path.

NGAP Handover (N2 HO) nb56

Synchronization Raster + HFN nb59
  • Synchronization Raster (5G NR): a set of predefined frequency locations where SSBs can be transmitted; these freq positions identified by the Global Synchronization Channel Number (GSCN). Enables efficient cell search — limiting potential SSB frequencies lets the UE search faster; used during initial cell search when UE has no prior knowledge of carrier frequency; applies across FR1 and FR2. How it works: each GSCN corresponds to a specific frequency where an SSB may be transmitted; UE scans these predefined frequencies to detect SSBs; freq associated with GSCN computed via standardized formulas.
  • HFN (Hyper Frame Number): a counter used in 5G NR (& LTE) to extend the range of sequence numbers for security. Ensures uniqueness of the "COUNT" value used in encryption & integrity protection algorithms. Maintains security & sequence number management. Used in PDCP & RLC layers (data encryption/integrity in control+user plane; UM & AM modes for sequence number management). Implicitly involved in security mode command & complete.
CORESET & Search Space Zero nb60
  • CORESET (Control Resource Set): defines a time-frequency region within a 5G NR carrier where the PDCCH can be transmitted. Specifies the resources allocated for DCI (scheduling assignments & control msgs). Each CORESET associated with one or more search spaces where UE decodes DCI (e.g. searchspace 1–10).
  • Search Space Zero: a predefined search space associated with CORESET#0. Determines the monitoring occasions & locations where the UE should look for PDCCH transmissions, particularly during initial access. Maintains initial access, efficient resource utilization, and support for multiple BWPs (network can manage control information across multiple BWPs, adapting to varying channel conditions). Configured in MIB transmitted via PBCH (CORESET#0 & searchspacezero). Other CORESET & search spaces configured via higher-layer signalling (RRC) for ongoing communication; each defines which DCI format can be decoded in that region.
Types of CORESET & Search Space in 5G NR nb61
  • CORESET types: CORESET#0 (implicit, derived from SSB/MIB; during initial access; carries SI and paging; UE uses it before RRC connection). CORESET#1,2… (explicit DCI 0_1/1_1; after RRC connection setup, configured via RRC reconfig; carries PDCCH for DCI scheduling e.g. PDSCH, Msg4, DRBs). CORESET used for SIB1 (may reuse CORESET#0 or a dedicated one; to carry SIB1 from MIB/SIB1; SIB1 may be mapped via searchspacezero or searchspace one). UE-specific CORESET (dynamic per UE; beam management, BWP switching, RRC signalling or MAC CE; used for dedicated scheduling e.g. VoNR, low-latency).
  • Search Space types: SearchSpace 0 (initial access, SIB1 scheduling, paging; CORESET#0; MIB/SIB1). SearchSpace 1 (RRC setup, Msg4, default UL grant; CORESET#0 or #1; SIB1 or RRC reconfig). UE-specific (dedicated UE DCI scheduling DL/UL grants, DRBs; CORESET#1/2…; RRC reconfig). SearchSpace for BWP switch (BWP-associated CORESET; RRC config or MAC CE). Paging (IDLE/INACTIVE; usually CORESET#0; SIB1). Random access (MSG2/RAR, MSG4; linked to CORESET#0/dedicated CORESET#1; MAC+RRC controlled).
Operating modes of RLC layer (AM / UM / TM) nb62
  • Three modes: AM, UM, TM — each offers a different level of reliability, latency and overhead.
  • UM (Unacknowledged Mode): no retransmission; used in voice/video (tolerate loss); for low-latency services that tolerate packet loss (e.g. VoLTE, VoNR); when speed matters more than reliability (real-time apps); DRBs, light header, small buffering; sequence number 6/12 bits.
  • AM (Acknowledged Mode): with retransmission; data (file transfer, signalling); ensures guaranteed delivery, reordering and retransmission; when data integrity is critical (e.g. RRC signalling, downloads); SRBs and DRBs; sequence number 12/18 bit, retransmission happens (HARQ + RLC retransmission), larger header, big buffer needed.
  • TM (Transparent Mode): no RLC header, no retransmission; used in broadcast messages like SIB; for broadcast/system info where minimal overhead is preferred (e.g. MIB/SSB on DL); during initial access or cell selection before RRC is even established; used in broadcast SRBs like SIBs (DL only); no buffering, no sequence number, no header.

(b) if RRC-CONNECTED: [process not yet defined].

Timing Advance (TA) nb78
  • What: TA is the timing offset applied by the UE so that its uplink transmissions arrive aligned with the eNB/gNB receiver's frame. It compensates the propagation delay between the UE and the cell.
  • Why: (i) synchronize UL transmission → prevent overlapping of multiple UEs' signals in UL; (ii) ensure uplink orthogonality → especially in SC-FDMA systems like LTE UL (one UE per subcarrier); (iii) accurate TDD scheduling → essential in 5G with dynamic TDD slots.
  • When: Initial attach → after RACH procedure. HO/RRC reconfig → if cell reselected / during mobility. MAC control loop → during connected mode (via TA command MAC CE).
  • Where: uplink transmission only (UE→eNB/gNB); in both LTE & 5G but mechanism differs slightly.
TA flow + formula nb79
  • LTE TA flow: Step1 MSG1 (PRACH) — UE sends preamble → eNB estimates timing offset. Step2 MSG2 (RAR) — eNB sends TA command (TA value) + TC-RNTI. Step3 — UE applies TA, adjusts its UL transmission time accordingly.
  • 5G NR TA flow: Step1 MSG1 (PRACH) — UE sends preamble → gNB estimates propagation delay. Step2 MSG2 (RAR) — gNB sends timing advance command (with time advance index & UL grant). Step3 — UE applies TA, same logic but with 5G TA granularity (TA = T_A × 16 × T_c).
  • Formula: Timing advance (in sec) = TA × T_s × N. T_s = 1/(15000 × 2048) sec. N = scaling factor (usually 16).
Application Protocol / DCI nb80
  • What is DCI: DCI is transmitted on PDCCH and tells the UE or gNB how to: receive downlink data (PDSCH); transmit uplink data (PUSCH); perform random access (PRACH); apply HARQ, scheduling, MCS, etc.
  • DCI formats in LTE (message / direction / DCI format / why):

Protocol Stack — PHY & MAC functions nb81
  • PHY (both): Modulation/Demod (converts bits↔waveforms: QPSK, 16/64/256QAM); Channel coding/Decoding (adds redundancy — Turbo, LDPC, Polar — for error correction); OFDM/DFT-S-OFDM (converts data for frequency-domain transmission, FFT/iFFT); MIMO/Beamforming (spatial multiplexing or signal focus using multiple antennas); Time/freq sync (proper alignment & tracking); DMRS/Pilots (channel estimation at receiver). *Directly impacts throughput, error rate, spectral efficiency. No PHY = no air interface.
  • MAC (both): Scheduling (decides which UE gets DL/UL resources, when & how many RBs — done by gNB/eNB MAC scheduler); HARQ (retransmits failed packets quickly using NACK feedback without full RLC resend); Multiplexing (combines multiple logical channels e.g. SRB, DRB into one TB); RACH (handles MSG1-MSG4 for initial access, contention resolution); Priority handling (manages prioritization of logical channels, e.g. SRB0>SRB1>SRB2>DRB1>DRB2); Buffer Status Report (BSR — UE tells gNB how much data it has waiting to send in UL); Scheduling Request (SR — UE sends SR to request uplink grant); DRX control (enables UE sleep cycles to save battery). *Core resource allocator; ensures fair & optimized use of air interface.
Protocol Stack — RLC & PDCP functions nb82
  • RLC (both): Segmentation (split large PDCP SDUs into smaller RLC PDUs to fit MAC TB size); Reassembly (rebuild original SDU from received RLC PDUs); Retransmission (AM mode — ensure lost RLC PDUs are retransmitted based on ACK/NACK feedback); Sequence Numbering (add SN to each PDU for reordering & loss detection); Reordering (in-order delivery to PDCP); Duplicate Detection (detect & discard duplicate PDUs on retransmission overlap). *Without RLC → unordered, incomplete data to PDCP or application.
  • PDCP (both): Header Compression (ROHC — compress IPv4/IPv6 headers to reduce overhead for VoLTE, IMS); Ciphering/Deciphering (encrypt/decrypt payload using keys from NAS security); Integrity Protection (ensure control-plane data not tampered — RRC, NAS messages); In-order delivery (reorder PDCP SDUs if RLC delivers out of order); Packet Duplication (send duplicate PDCP PDUs to improve reliability — dual connectivity / 5G); PDCP SN management (add PDCP SN for reordering, loss detection). *Without PDCP → no security, no handover continuity.
Protocol Stack — SDAP & RRC functions nb83
  • SDAP (5G only, user plane): QoS Flow to DRB Mapping (maps each 5G QoS Flow ID QFI to a specific DRB); QoS Enforcement (ensure traffic handled per 5QI — latency, priority); QFI tagging (add small header identifying QoS Flow ID); Traffic Differentiation (helps slice-aware scheduling by service class, e.g. URLLC vs eMBB). *Ensures true network slicing & per-service QoS in 5G.
  • RRC (control plane): RRC state management (handles transitions RRC_IDLE ↔ RRC_CONNECTED ↔ RRC_INACTIVE); SRB/DRB config (setup SRBs control & DRBs user plane); Mobility & HO control (commands intra/inter-cell handovers); Measurement configuration (instruct UE when/how to measure neighbour cells); Security Activation (applies keys K_RRCint, K_RRCenc, K_UPenc from NAS layer); System Information Delivery (delivers SIBs & handles SI requests); UE capability exchange (request & receive UE radio capabilities); DRX/power-saving setup (configure DRX cycles at UE). *RRC is the brain of UE-gNB signalling.
Protocol Stack — NAS functions nb84
  • NAS (Non-Access Stratum, control plane): Authentication (performs 5G-AKA/EAP authentication b/w UE & AMF/MME); Registration/Attach (UE registers with AMF in 5G or attaches to MME in LTE); Session Management (sets up PDU sessions 5G or bearer setup LTE); Mobility Management (handles Tracking Area Update TAU, deregistration, paging); Security key derivation (derive AS-level keys: K_AMF → K_UPenc, K_RRCint etc.); Bearer context management (NAS maintains default & dedicated bearer info); Transport of NAS Msg (encapsulated inside RRC messages — RRCSetupComplete, Security Mode Complete). *All UE↔core logic passes through NAS — attach, IP allocation, mobility, etc.

Throughput factors — what impacts each factor nb86b
  • CQI: maps to MCS → higher CQI = higher MCS → ↑throughput. Impacted by: SINR, interference, fading, mobility (Doppler), multipath.
  • MCS: decides bits/symbol; high MCS → ↑bits/TTI. Impacted by: CQI, BLER, scheduler conservativeness, UE category.
  • RB allocation: more RBs → wider BW → ↑throughput. Impacted by: scheduler decision, load on cell, UE capability, QoS priority.
  • HARQ: more retransmits → wasted time → ↓efficiency. Impacted by: BLER, interference, SINR, radio-frame conditions.
  • Scheduling: controls RB + timing assignment. Impacted by: CQI reports, BSR (for UL), network congestion, slicing priorities.
  • RLC (AM/UM): AM retransmits → ↑reliability but ↓real-time throughput. Impacted by: channel loss, delay, mode config.
  • DRX: idle mode to save power → ↓data reception slots. Impacted by: DRX config (on/off duration), inactivity timers.
  • PDCP/ROHC: inefficient compression = larger overhead. Impacted by: app headers (VoLTE vs browsing), ROHC config.
  • SINR/SNR: poor SNR = low CQI = low MCS. Impacted by: interference, path loss, fading, cell edge, UE speed.
  • UE power: limits modulation & BW in UL. Impacted by: battery, thermal issues, power class.
  • UL TPC: wrong power = UL CRC errors = low throughput. Impacted by: bad closed-loop power control, fading, TPC misconfig.

Cell Reselection formula + Qoffset + S-IntraSearch nb91
  • Cell Reselection formula: Srxlev = RSRP − q-RxLevMin − P_compensation. Squal = RSRQ − q-QualMin.
  • Cell is suitable if: Srxlev > 0 AND Squal > 0. And reselection is allowed if: ServingCell Quality < threshServingLow for t-reselection seconds.
  • Qoffset (aka q-OffsetFreq, q-OffsetCell): an offset in dB (−24 to +24) applied to the measured RSRP/RSRQ of a neighbour cell/freq — to penalize or favour certain cells/freqs during ranking. Adjusted signal level = Measured RSRP − Qoffset. A negative Qoffset improves cell rank; a positive Qoffset lowers cell rank. Example: measured RSRP = −92 dBm, Qoffset = +6 dB → effective RSRP = −92 − 6 = −98 dBm.
  • S-IntraSearch, S-NonIntraSearch (SIB3 LTE, SIB5-7 5G... [as noted]): thresholds that trigger searching for new cells. To reduce UE power consumption — no need to measure neighbours unless needed. If serving cell RSRP > s-IntraSearch → UE does not search. If serving cell RSRP < s-IntraSearch → UE starts neighbour scan. If Srxlev (serving cell) ≤ s-NonIntraSearch → UE starts (or is allowed to do) inter-freq or inter-RAT search.
LTE & 5G Cell Selection and Synchronization Flow nb92
  • LTE (on UE power on): (i) Stored cell try — UE checks last camped frequency + PCI stored in memory; if cell valid (not barred + PLMN OK) → camp & proceed. (ii) If stored cell fails → frequency scan — UE scans supported LTE bands for PSS/SSS (DL sync signals); detects PCI & syncs timing/freq. (iii) If no suitable cell found — UE may perform a broader freq range sweep; eventually may camp on any emergency cell.
  • 5G (on UE power on, SA mode): (i) Stored cell try — UE checks last used freq + SSB index; if valid try to decode SSB → then MIB → then SIB1. (ii) If stored cell fails → SSB beam scan — UE scans SSB beams over a configured sync raster; each SSB = PSS+SSS+PBCH and is beamformed (not omnidirectional like LTE); finds best SSB index with strongest signal (based on RSRP/SINR). (iii) SSB sync & decoding — PSS = symbol-level sync; SSS = frame timing + PCI; PBCH = MIB; then decode SIB1, check PLMN, q-RxLevMin, TAC, etc.

Scheduling Request (SR) — MAC level nb94
  • Scheduling Request (SR) — MAC layer; Service Request (SR) — NAS layer. (Two different "SR"s!)
  • Scheduling Request (aspect / detail): Layer = MAC (L2). Purpose = UE requests uplink resources from gNB/eNB to send data (on PDSCH grant). Trigger = UE has data to send (e.g. RRC/NAS message or user data). How sent = on PUCCH using SR format. When needed = when UE is configured for SR & has no active UL grant. Response = gNB grants UL resource via DCI 0_0 (5G) or 0 (LTE).
  • Typical scenario for SR: UE is in RRC-CONNECTED; UL grant has expired or was not allocated; UE wants to send RRC message (e.g. RRCReestablishmentReq), NAS message (e.g. Service Req), or UL user data. UE first sends MAC SR → gets UL grant → then sends data (RRC or NAS).
Service Request (NAS) + key messages nb95
  • Service Request (aspect / detail): Layer = NAS (Non-Access Stratum, UE→AMF/MME). Purpose = UE asks the core network to resume/re-establish a session. Trigger = UE is in RRC-IDLE or RRC-INACTIVE and needs to send/receive data. How sent = over UL NAS Transport after RRC connection req/setup. When needed = after UE triggers mobility or data activity. Response = network sends authentication, security, PDU session resume, etc.
  • Typical scenario for NAS service request: UE is idle (to save battery/data); user opens app / VoLTE call arrives; UE does RRC resume/setup → sends Service Request to AMF/MME. Used for resuming bearer context & PDU session (NOT for UL resource request — that's the MAC SR).
  • Key messages (MAC level SR): SR on PUCCH (UE→eNB/gNB) — UE asks for uplink resources. DCI 0_0/0 (gNB→UE) — grants PUSCH for UL data.
Service request (NAS) procedure + Scheduling Request (MAC) deep facts nb96
  • Service request (NAS level): UE in IDLE→resume | RRCConnectionReq / RRCResumeReq. RRC connection setup/resume | RRCConnectionSetup, RRCResume. NAS service request | sent in UL NAS Transport. Response | Authentication → Security → Initial Context Setup.
  • Scheduling Req (MAC) — you should know: Trigger condition = when UL buffer has data + no active grant. UE behaviour = sends SR over PUCCH (format 1/2/3). Configuration = SR periodically, max SR retries (via RRC→MAC config). What happens after SR = gNB schedules DCI 0_0/0 with PUSCH → UE sends data. Failure/no grant = SR retry timer starts; after retries, UE may drop data or escalate. SR collision with BSR = if BSR is available, SR may be skipped. SR with DRX = SR opportunity occurs at on-duration or DRX cycle start. Where to see it in logs = MAC logs "scheduling req sent on PUCCH", check DCI grant after it. Common issues in field = no grant → UL delay, VoLTE mute, RACH fallback.

Service request fail + Scheduling request fail nb98
  • Service request resume: if UE is in RRC-INACTIVE, it sends RRCResumeReq to the gNB, followed by UL NAS Transport → service request. If UE is in RRC-IDLE, it starts from scratch with RRCSetupRequest → RRCSetup → RRCSetupComplete → service request.

BSR — Buffer Status Report nb99
  • BSR is a MAC control element sent by the UE to inform the gNB/eNB about the amount of data (in bytes) waiting in its uplink buffer (RLC) per logical channel group. Used to let the gNB/eNB know how much uplink data the UE has. Enables uplink scheduling → gNB starts allocating resources (PUSCH). Prevents buffer overflow and supports QoS prioritization.
  • When BSR triggered: new uplink data arrives and no pending grant available; expiry of BSR timers; UE gets uplink resources (SR or dynamic grant); logical channel group becomes empty or non-empty; upon reconfiguration.
  • Where BSR used: MAC layer → sent as a MAC control element (MAC CE); part of MSG3 in RACH or dynamic PUSCH transmission.
  • How BSR works: UE maintains separate buffer status per LCG (Logical Channel Group). BSR formats: Short BSR (1 LCG); Truncated BSR (2 LCGs); Long BSR (all 4 LCGs LTE / 8 LCGs in 5G). Triggered via Scheduling Request (SR) or directly on PUSCH.
BSR configuration / edge cases / RACH / LCG mapping nb100
  • BSR configuration controlled by: BSR-Timer (if running, BSR transmission is delayed); retx-BSR-Timer (re-triggered if last BSR was not successfully transmitted); logicalChannelGroup (mapping of DRBs to LCGs — very useful for understanding what traffic each BSR represents).
  • Triggering edge cases — BSR not sent when: UE already has enough grant (resource) to send the buffer; there is no new data, or the same BSR is already pending; if MAC CE BSR was transmitted but not acknowledged, reattempt waits for retx-BSR-timer.
  • BSR during RACH: initial BSR is critical — sent during MSG3 → used by gNB to assign dynamic UL grant. If MSG3 is not decoded, BSR is lost → RACH retry needed.
  • LCG mapping example: LCG ID 0 → SRB (signalling); 1 → QCI 1 (VoLTE/IMS); 2 → QCI 6 (video); 3 → QCI 9 (default).
PHR — Power Headroom Report nb101
  • PHR tells the gNB/eNB how much transmit power headroom the UE has left — the difference between maximum allowed power and current transmit power.
  • Why PHR used: enables gNB to decide how much UL resource to assign; understand if UE is power-limited; manage link adaptation, beamforming, and MCS.
  • When PHR triggered: change in pathloss exceeds threshold; PHR timer expires; change in transmit power; new serving cell / SCell addition; configured explicitly by gNB.
  • Where PHR used: MAC layer, sent as MAC CE; applied per serving cell (PCell, SCell).
  • Formula: PHR = P_max − P_used. P_max = max UE transmit power; P_used = estimated power used for last UL transmission. PHR mapped into discrete values (PHR index from 0 to 40).
  • Types of PHR: Regular PHR — sent per PCell/SCell. Extended PHR — includes PHR for SCells separately.
PHR params + Handover Failures (intro) nb102
  • PHR params: Prohibit timer → avoid frequent updates. DL pathloss change trigger → triggered when pathloss changes beyond threshold. PH-Type2-OtherCG → used when UE is connected to 2 cells (e.g. dual connectivity); reports power margin on other CG. PH-Info → contains actual PHR value and validity flag.
  • Uplink scheduling consideration: if UE has low PHR, gNB may lower MCS, avoid wide-bandwidth grants, avoid scheduling on SCell.
  • PHR usage in Dual Connectivity (EN-DC/NR-DC): UE needs to send PHR for both gNB and eNB. Specific MAC CE formats exist for: PHR-Type1 (per serving cell); PHR-Type2 (cross-cell group power margin).
  • HANDOVER FAILURES: a HO failure happens when the UE fails to successfully complete the transition from one serving cell (source) to another (target), resulting in radio link failure (RLF), call drop, or fallback to the previous cell or re-establishment.
  • When & where do HO failures happen (phase / failure point):
  • Measurement → bad/corrupt measurement reports, not triggering A3/A5 properly.
  • HO preparation → context setup at target fails.
Handover Failures — phases + causes nb103
  • Phases (phase / failure point): HO Execution → HO command not received, decoded or applied. HO Completion → UE fails to synchronize with new cell or misses timing. Post HO → path switch failure, security failure, NAS re-attach needed.
  • Why do HO failures happen:
  • Radio Link Issues: low RSRP/RSRQ/SINR in target cell; interference or fading; fast-moving UE (mobility >120 km/h).
  • Incorrect or Delayed measurement config: wrong or late triggering of A3/A5 event; UE sends late MR; threshold too high/low → unnecessary or no HO.
  • Timing & Resource Issues: target cell cannot allocate RRC/PDCP context; UE misses HO command; target cell rejects HO request.
  • Core & Signalling Failure: path switch request failure (X2/Xn/S1); HO command arrives too late (UE already left coverage); security context mismatch after HO.
  • Configuration/Parameter Issues: incomplete LTE/5G configs (MIMO, bandwidth, CA); SIB1/5 info mismatch; gNB not updated in neighbour list.
  • Summary of failure points: MR delayed or invalid; target rejects HO request; UE misses or drops HO command; MSG3/MSG4 RACH failure at target; path switch failure at MME.
HO failure resolution + Hysteresis nb104
  • How to resolve HO failures (issue type → resolution):
  • Poor SINR/RSRP → tune thresholds (A3 offset, TimeToTrigger), optimize antenna tilt, reduce interference.
  • RACH MSG3/MSG4 failure → verify PRACH config, RACH resources, HARQ retries.
  • HO command not received → improve paging timing, HO execution time.
  • HO prep fail → verify neighbour list, ensure target has sufficient context config.
  • Wrong A3 config → adjust A3 offset & hysteresis to reduce ping-pong.
  • AMF/MME rejects path switch → check S1/X2/Xn status, update neighbour relations.
  • Beam failures in 5G → adjust beam sweeping interval, tune beam threshold.
  • TimeToTrigger = time UE must continuously satisfy A3/A5 condition before sending MR.
  • Hysteresis = prevent ping-pong (HO) between cells by adding margin to event triggering. E.g. if A3 offset = 3 dB, TTT = 160 ms, then UE triggers HO only if neighbour RSRP > serving RSRP + 3 dB continuously for 160 ms.
  • HYSTERESIS: a margin (in dB) added to delay reselection or handover decision to prevent ping-pong between similar-strength cells (cell reselection, HO, etc.). Typically 0-10 dB, mostly 3 dB.
Hysteresis usage + Scheduling in LTE/5G nb105
  • Key parameters paired with Hysteresis (scenario / paired parameter / purpose):
  • Cell Reselection | q-RxLevMin / Srxlev / Squal | compare measured signal level against min required + hysteresis.
  • Measurement Event A3 (HO trigger) | A3-offset | event triggers when target cell becomes better than serving + offset.
  • Inter-freq reselection | threshX-High, threshX-Low | compare target & serving cell levels with offset.
  • Inter-RAT reselection | q-OffsetFreq / q-OffsetCell | adds/removes bias to particular frequencies/cells in reselection ranking.
  • Formula: Srxlev = RSRP_meas − q-RxLevMin − P_compensation. Cell suitable if Srxlev > 0. Reselection when Neighbour Srxlev > serving Srxlev + hysteresis. Event A3: RSRP_neighbour > RSRP_serving + A3-offset + hysteresis.
  • SCHEDULING in LTE/5G: how the network (MAC scheduler) decides when, how much, and on which resources (time-frequency) to allow the UE to transmit or receive data. MAC scheduler allocates PDSCH (DL) & PUSCH (UL) using DCI messages over PDCCH.
  • Types: Dynamic (new UL/DL resource grant sent for every transmission); Persistent (fixed static allocation, very stable/reserved networks); Semi-persistent (resources pre-configured and reused periodically, e.g. VoLTE).
Dynamic / SPS / Persistent scheduling nb106
  • Dynamic scheduling: used for bursty, unpredictable traffic like web/app data. At each TTI (1 ms LTE, 0.125-1 ms 5G) based on buffer and CQI. PDSCH (DL), PUSCH (UL). gNB sends DCI 0_0 (UL) or DCI 1_0 (DL) with exact RB allocation. Advantage = very flexible, efficient use of resources. Disadvantage = high overhead (DCI every time), not power efficient.
  • Semi-Persistent Scheduling (SPS) [UE requests then network sends]: used for periodic, predictable traffic like VoLTE/VoNR. UE configured once via RRC, then repeat use of resources periodically. DL & UL (especially for voice or safety messages). SPS config indicates periodicity, PUCCH SR config, UE knows when to send. Activation done via DCI with SPS activation bits. Deactivation done explicitly via DCI or timer expiry. Advantages: lower DCI overhead, reduced UE power consumption. Disadvantages: less flexible, can waste RBs if data not ready.
  • Persistent scheduling (very rare) [5G URLLC/slicing, not used in LTE]: used in special use-cases (e.g. fixed allocation for critical M2M). Static allocation at config, remains unchanged. Mainly theoretical or vendor-specific. Sent in RRC, does not rely on DCI. Example: fixed telemetry channel in 5G slicing.
  • RRC reconfig config keys: LTE → sps-config: semiPersistSchedIntervalDL sf20, semiPersistSchedIntervalUL sf20. 5G → schedulingRequestResourceConfig: periodicity ms20, sr-ResourceId 1; ConfiguredGrantConfig: grantType type2, timeDomainOffset 4.

VoLTE Call Drops — categories & symptoms nb107
  • VoLTE (Voice over LTE) is a real-time, IMS-based voice service over the LTE data bearer (QCI 1). Call drops happen when the voice bearer is abnormally released or media/signalling fails.
  • Main categories (category / common causes / why it leads to drop):
  • Radio/RAN | weak RSRP/RSRQ/SINR, fading, poor HO | bad signal → RLC/PDCP discard → RTP lost.
  • RLC/MAC | HARQ failures, BSR/PHR issues | uplink RTP packets not transmitted.
  • eNB/gNB | improper HO config, context loss, request timeout | UE drops connection or resets.
  • Core/IMS | SIP 481/408 errors, call session release | IMS rejects SIP signalling → call ends.
  • Bearer/QoS | QCI 1 bearer missing, DRB drop, DL throughput stall | RTP cannot flow → silent call then drop.
  • SRVCC/CSFB | poor fallback or late trigger | call drops during inter-RAT HO.
  • DRX/Timers | aggressive DRX cycle, inactivity timeout | DRB deleted too early, call closed.
  • UE Issues | weak modem, timer mismatch, battery | UE fails to keep sync or respond.
  • SIP re-invite/update fails: SIP 4xx/5xx (408, 418, 480, 500 = temporarily unavailable / server internal error) → IMS registration lost, QCI 1 released → SIP BYE, packet delay/jitter.
  • Technical symptoms (symptom / underlying cause): No RTP packet after HO → bearer not resumed / wrong QoS. SIP BYE or 408 → IMS registration lost / SIP timeout. Sudden DRB release → UE power-limited or DRX misconfigured. SRVCC fails → BSR/PHR not sent, MSG3 failure on 2G/3G. Call drop at cell edge → UL/DL SINR poor, late HO trigger.
VoLTE drop resolution + Call Mute vs Drop + RTP nb108
  • How to resolve/improve VoLTE call drop rate (action / benefit): Optimize HO thresholds (A3, TTT) → reduces RLF and late HOs. Check DRB inactivity timers (T-inact) → prevents premature bearer release. Increase PHR/BSR timer granularity → keeps UL voice flow alive. SIP timers tuning (T1, T2, etc.) → avoid SIP timeout drops. Improve beam coverage (5G) or antenna tilt (LTE) → ensure strong RSRP/RSRQ for voice bearer. QCI handling tuning → verify scheduler treats QCI 1 with highest priority. Activate SRVCC/VoLTE fallback in poor LTE zones → prevent coverage-induced drops. Enable RTP loopback testing in lab → catch UL/DL stalls early.
  • Call Mute: media path is broken but signalling stays → RTP lost due to one-way path, low SINR, HARQ (causes: DRX, bad UL SINR, RTP port blocked).
  • Call Drop: complete release — SIP release (BYE or 481) or RLF causes full call termination (causes: RLF, SIP BYE, DRB failure, IMS timeout).
  • RTP (Real-time Transport Protocol): a protocol used to deliver audio and video data in real-time applications — like VoLTE voice, video calls, live streaming, etc.

X2 Handover call flow (4G LTE) + RACH FAILURES nb112-113
  • X2 Handover (LTE): source eNB → target eNB (X2AP HO request/ack), RRC reconfiguration to UE, SN status transfer, data forwarding; then Path Switch Request (target eNB → MME) → MME modifies bearer with SGW [EPS bearer ID, TEID; UE-AMBR, E-RAB to be switched uplink (erab ID, GTP-TEID, E-RAB to be released, security context)]; Path switch ACK [old eNB-UE-X2AP-ID, new eNB-UE-X2AP-ID]; UE context release (target→source).
  • RACH FAILURES: RACH = random access channel, used by the UE to initial access to the network. When: UE power on; RRC-IDLE→connected; during HO; during RRC or SR. It is contention-based or contention-free (UL step).
  • Step1: UE sends PRACH preamble → MSG1. Step2: eNB/gNB responds with RAR (TA, UL grant) → MSG2. Step3: UE sends RRC or MAC CE using grant → MSG3. Step4: eNB/gNB sends contention resolution (if needed) → MSG4.
  • RACH failure (phase / cause / description): MSG1 → low RSRP/SINR → UE PRACH preamble not detected at eNB/gNB. MSG2 → downlink decoding issue → UE does not receive RAR (during HO). MSG3 → UL grant too small, poor UL power → MSG3 not decoded correctly. MSG4 → contention resolution failed → multiple UEs used same preamble (low SINR), wrong preamble format, root seq index timing.
  • What impacts RACH success (factor / impact): SIB2 configuration → wrong preambleTransMax, no-response window size, msg3-HARQ limit, wrong preamble format can cause failure.

NB14 Notes — ANR Timers, 5G Location Services, EN-DC SgNB Addition & ETWS Notes click to expand ▾
Max-ANR-Attempts / ANR-Pending-Timeout / Neighbor-Keepalive / PCI-Collision-Resolution ANR timers
  • Max-ANR-Attempts: counts how many times the same PCI was reported but failed to provide CGI. Stop when successful CGI received & neighbour added. If expired → PCI blacklisted or suppressed for X minutes/hours. Prevents repeatedly triggering failed ANR attempts (e.g. weak PCI or missing SIB).
  • ANR-Pending-Timeout: starts after measurement report with A4 PCI (unknown) received. Stops when CGI report is triggered (eNB sends RRC config). If expired → PCI entry dropped or considered stale. Buffer window before triggering actual CGI config (debounce/delay ANR start).
  • Neighbor-Keepalive-Timer: starts per known neighbour after it has been added to NRT. Reset every time PCI is reported again in MR. If expired → neighbour entry removed or marked "unused". If a neighbour is not seen in recent MRs it may be dynamically pruned from NRT.
  • PCI-Collision-Resolution-Timer: starts when two cells report same PCI from different ECGIs. Stops when conflict is resolved (CGI learned or blacklist). If expired → one PCI kept, other blacklisted. Helps resolve PCI confusion (same PCI reused in different areas).
5G NR Location Based Services Architecture 5G LBS
  • AMF receives request for a location service associated with a particular target UE from another entity (GMLC or UE), OR AMF itself decides to initiate a location service on behalf of a target UE (e.g. for an IMS emergency call). AMF sends the location service request to an LMF. The LMF processes the request which includes: transferring assistance data to the target UE (UE-based and/or UE-assisted positioning) and/or positioning of the target UE. Then LMF returns the result back to AMF (e.g. a position estimate).
  • Architecture: UE —NR-Uu— gNB(TRP) / ng-eNB(TP) [NG-RAN] —NG-C— AMF —NL1— LMF (··· E-SMLC / SLP); Xn between ng-eNB & gNB.
  • LMF (Location Management Function): manages support for different location services for target UEs (UE positioning, delivering assistance data). It interacts with gNB to obtain position measurements for the UE.
Initial Context Setup / SgNB Addition IEs (EN-DC) nb NSA
  • UE Aggregate Max Bit Rate (IE, mandatory): the Master Node allocates some or all of the UE-AMBR to the SgNB (secondary node) during the secondary cell addition procedure (using X2AP, SgNB Addition Req).
  • E-RAB to be Setup list: E-RAB Identity & QoS parameters (IE, mandatory) — may include non-GBR bearer with QCI 6-9, non-GBR bearer with QCI 5 for signalling to an IMS. Only UEs with a specific ARP value are considered for secondary cell addition. Transport layer Address & GTP-TEID (IE, mandatory) — S1-U IP address of SGW and GTP-TEID; GTP-U is used between the RAN and the core to carry the user-plane IPv4/v6 data.
  • Handover restriction list, UE Radio Capability, SPID, NR UE security capabilities (optional).
ETWS (Earthquake and Tsunami Warning System)
  • Two types: Primary (SIB6), Secondary (SIB7). Primary should be delivered in useconds (fast). ETWS comes in SIB1 in SI.
  • Primary notification contains: message identifier (16 bit) [1100 = tsunami, 1101 = earthquake, 1102 = both]; serial number (16 bit); warning type (octet string, size 2).
  • warning-type value (7 bit): 0000000 = earthquake, 0000001 = tsunami, 0000010 = both, 0000011 = test, 0000100 = other, 0000101-1111111 = reserved for later. Plus emergency-user-alert popup: binary (0/1) and popup binary (0/1) — 0 means no instruction, 1 means activate.

Interview Q&A
Q: Name the main RAN KPI categories and one KPI in each.
A: Accessibility (RRC/E-RAB setup success), Retainability (call/session drop rate), Mobility (handover success rate), Integrity (DL/UL throughput, latency, BLER), Availability (cell availability), and Utilisation (PRB utilisation) — plus voice KPIs like VoLTE drop rate. Each maps to a counter ratio and a set of degradation causes.
Q: Accessibility KPI dropped in a cell — how do you troubleshoot?
A: Split it: RRC setup success (RACH/preamble, congestion, admission) vs E-RAB setup success (core/transport, QoS, licensing). Check RACH counters and preamble/MSG failures, PRB/CPU load, admission-control rejects (ARP), and S1/NG transport. Correlate with RSRP/SINR to rule out coverage.
