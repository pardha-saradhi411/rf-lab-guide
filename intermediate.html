M09 AAU Architecture — FHGW + RFFE internals, DPD observation loop, beamforming split Advanced click to expand▾
PLAIN ENGLISH FIRSTAAU architecture in one sentence: Your Metro AAU has two boards — a digital board (midBRD) that processes the signal and a radio board (RFFE) that amplifies and transmits it — and four columns (A/B/C/D) each doing this independently so they can steer the beam.

AAU architecture — midBRD, RFFE, board split, 5-band design

5-Band AAU board structure:
Your Metro AAU has two main boards: midBRD (mid-band board) handles B1 (2140 MHz) and B3 (1843 MHz) digital processing, DAC/ADC, and digital beamforming. RFFE boards (RF Front-End) handle the analog RF — PA, LNA, duplexer, BPF — for each column. B8 (900 MHz), B28 (758 MHz) are low-band and handled by a separate LB RFFE. B41 (2545 MHz TDD) shares the mid-band RFFE with B1/B3. The midBRD connects to RFFE via JESD204B high-speed serial interface.
Single DPD observation path — shared between bands:
DPD needs to observe the PA output to adapt. A single observation receiver (ORX) path is shared between B1, B3, and B41 — it cannot observe all bands simultaneously. The DPD engine time-shares the ORX, adapting one band at a time. When you change power on one band, the DPD for that band re-adapts while others hold their last coefficients. This is why individual band power changes take 60s for DPD to re-converge.
4T4R vs 4T2R vs 2T2R — flavour impact:
4T4R: all 4 columns (A/B/C/D) active for TX and RX — full beamforming, best capacity. 4T2R: 4 TX columns but only 2 RX — used for LB (B8/B28) where 2 RX paths are sufficient. 2T2R: reduced mode for lower power operation. The flavour (b1b3, b1b3b41, b1b3b8b28b41) determines which bands are active simultaneously and which columns are used — directly affecting DSA values and RX path counts in the test table.

Antenna arrays and beamforming gain
B1/B3/B41: 4-2-2-4 element arrangement (12 elements, 4 columns) → beamforming gain ~+12 dB. B8/B20/B28: 3-3 (6 elements, 2 columns) → beamforming gain ~+6 dB. This is why TRP is 6–12 dB higher than per-PA output power.
Single shared DPD — the calibration observation loop
One shared DPD cannot watch every PA simultaneously. The solution: directional couplers tap each branch, and a switch matrix (SW1…SW25) routes ONE branch at a time to a shared observation receiver (OBS). That OBS feeds the DPD/calibration engine. The same loop runs TX CAL, RX CAL, and OB CAL.
The calibration switches must be absorptive (50Ω at all ports) with isolation >40 dB at 2.7 GHz. If they're not — unused paths leak into the observation path, corrupting the DPD model → ACLR degrades.

RFFE TX path — what each block does and common faults

midBRD to RFFE interface — JESD204B:
The midBRD (digital board) sends IQ samples to the RFFE (analog board) via JESD204B — a high-speed differential serial interface running at 122.88 MSPS per lane. Each band has its own lane pair. If the JESD204B link goes down (clock drift, cable fault on the board-to-board connector), that band loses its TX signal entirely. Symptom: TX power = 0, no ACLR error, just silence. Debug: check JESD lock status register on midBRD.
PA — the highest-risk component on the RFFE:
Each PA is a separate GaN device per band per column. 12 PAs total (3 bands × 4 columns). Common failure modes: (1) Over-temperature: ambient > 55°C causes thermal derating, > 85°C junction causes shutdown. (2) VSWR: bad antenna connection reflects power back into PA — VSWR > 3 triggers protection. (3) Over-current: wrong OVERCURRENT register (default 0xFF = disabled protection — always set correct value). (4) ESD damage from careless connector handling. PA failure = that band/column TX dead, other bands/columns unaffected.
BOB SMA coupler — why −30 dB:
The directional coupler taps a fixed fraction of the main TX signal (−30 dB = 1/1000th of power) and routes it to the BOB SMA port for measurement. The main path continues to the antenna unaffected. At B1 rated power (+43 dBm antenna), BOB SMA = +13 dBm. Add 30 dB attenuator pad: EXA input = −17 dBm. Your rated target at BOB SMA (−16.7 dBm for B1) already accounts for the coupler ratio — so comparing EXA reading to −16.7 dBm target directly gives you the pass/fail without any manual correction.

Single DPD architecture — one observer for three PAs
Notice the diagram shows THREE separate PAs (one per band) but the coupler taps all three. The single DPD block on the FHGW cannot observe all three simultaneously — the switch matrix (SW1–SW25) routes one band at a time to the shared observation receiver. DPD adapts the model for B7 PA, then switches to B1 PA, then B3 PA, cycling through them. This is the "single DPD" architecture referenced in the original AAU block diagram document (1.6m 6 AAU Block Diagram_B1B3 single DPD V0.2.vsdx).

FHGW DL processing chain — what each block does

BFP decompression — restoring full IQ precision:
The DU compresses IQ samples before sending over eCPRI: 16-bit samples → 9-bit mantissa + 4-bit shared exponent per resource block. The FHGW must exactly reverse this. BFP expansion error corrupts IQ amplitudes by powers of 2 → RSSI steps of 6 dB, EVM degradation, PRACH detection failures. If you see unexplained 6 dB RSSI jumps between columns, suspect BFP — check FHGW firmware version and eCPRI error counters.
CFR and DPD — the two linearisation stages:
CFR (Crest Factor Reduction) clips signal peaks above a threshold, then filters to restore spectral shape. Reduces PAPR from 12 dB to ~8 dB. Aggressive CFR improves PA efficiency but degrades EVM. Too much clipping = EVM failure even before the PA.

DPD (Digital Pre-Distortion) applies the inverse of the PA's nonlinearity. The PA then "un-distorts" back to linear. DPD learns the PA's behaviour via the ORX observation path. If DPD diverges (coefficients go unstable): ACLR suddenly worsens by 10–15 dB. Check DPD_STATUS register. Re-enable to force re-convergence.
DFE — Digital Front End:
DFE performs interpolation (upsampling from symbol rate to DAC rate) and frequency shifting (moving the baseband signal to the correct IF frequency before DAC). A DFE configuration error puts the signal at the wrong frequency → TX power at correct band is zero, but a spurious signal appears elsewhere. Check DFE_FREQ_OFFSET register if TX power is missing but no fault is logged.

CFR and PAPR — the most misunderstood part of this diagram
People expect power to DROP through every stage (gain < 0). But notice: power RISES from −15.2 dBFs to −8.8 dBFs across the CFR block (+6.4 dB). This seems impossible — the CFR is supposed to clip peaks, not add power. Here is what actually happens:
An OFDM signal has high PAPR. The average power is low but the peaks are high. When you clip the peaks, you remove the energy in those peaks — but the average power calculation is dominated by how often each amplitude occurs. CFR clips just the rare high peaks, but their removal means the waveform can now run at a higher average power without clipping the ADC/DAC. In practice: after CFR, the entire waveform is scaled UP so the clipped peaks sit at the DAC full-scale limit. The average power rises because the distribution is now less peak-heavy. The PAPR goes from ~11 dB to 8.3 dB — meaning the signal is now 8.3 dB more "compact" — and this compactness is the gain.
The CFR threshold = 8.3 means clip everything above 8.3/10 = 83% of full scale. wcfr_threshold = 8.5 is the wide-CFR threshold — a second pass that clips wider peaks. filter_length = 511 is the FIR smoother length — longer = better spectral containment but more latency. These values are tuned so EVM stays within 3GPP limits (clipping adds EVM) while ACLR also passes (too little clipping = PA runs too backed-off = inefficient, too much = spectral splatter).

The B28 power deficit — exactly what happened
Your open investigation: B28 shows ~3 dB output power deficit between firmware builds. Looking at this diagram: the most likely cause is a change to the DAC Output Scale register (DAC Current value). The diagram shows DAC Current [28318] = −2.87 dB. If a firmware update accidentally changed [28318] to a lower value (e.g. 20000 → different dB offset), the output power drops by exactly that difference. PWK confirmed it was a DAC setting change between builds. The fix: restore the correct DAC current register value for B28 on the affected firmware build.
Never change DAC current registers without first noting the current value and verifying output power against P_rated. A 1-register change here affects every test: Tx power, ACLR, EVM, SEM — all measured relative to the expected output power level.

Reading real lab screenshots — EXM ACP and Modulation Analysis

EXA ACP display — field by field:
The ACP (Adjacent Channel Power) screen shows: Main channel power = your TX output (should match rated target ±1 dB). Adj channel = power at ±1 channel offset — this is ACLR. Alt channel = power at ±2 channels — stricter limit. Channel bars = blue = main, orange = adjacent, red = limit exceeded. If any bar is red: FAIL. Most common cause: DPD not converged (measured too soon after TX enable). Wait 60 seconds and re-measure.
Modulation Analysis constellation — what each shape means:
Tight grid of clusters: excellent — all symbols hitting their targets. Fuzzy/spread clusters: phase noise (LO) or SNR too low. Clusters offset from origin: DC offset / LO leakage. Clusters compressed along one axis: IQ amplitude imbalance. Grid rotated: IQ phase imbalance. All clusters compressed inward: PA compression — DPD not working. Asymmetric spread on one side: memory effect in PA (DPD model order too low).
EVM percentage — reading the number:
EVM is shown as a percentage. Lower = better. Limits: QPSK < 17.5%, 16QAM < 12.5%, 64QAM < 8%, 256QAM < 3.5%. An EVM of 2.5% on 64QAM is excellent. An EVM of 9% on 64QAM is a fail. Real lab screenshots — EXM ACP, Modulation Analysis decoded

Reading the EXM ACP screenshot:
ACP (Adjacent Channel Power) display on EXM shows: centre channel power (your rated output), adjacent channel power at ±offset frequency, alternate channel at ±2× offset. The ratios between adjacent and centre are ACLR values. Red bars exceeding the mask = FAIL. Vertical axis: power in dBm. Pass criterion: adjacent channel ≥ 45 dB below centre. Check: is DPD converged? Is measurement BW correct for your channel BW?
Reading the Modulation Analysis (constellation) display:
EVM display shows IQ constellation plot. Good result: tight clusters at each QAM point, all within the decision boundary. Problems: Spread clusters = phase noise (LO quality). Clusters offset from grid = DC offset (LO leakage). One axis compressed = IQ amplitude imbalance. Rotated grid = IQ phase imbalance. All points compressed inward = PA compression. Each fault pattern gives different constellation shape — learn to read them.
EXM screenshot — what each field means:
Carrier freq: your configured DL centre frequency. Output power: measured conducted output (before coupler loss). EVM rms: overall modulation quality (pass < 8% for 64QAM). EVM peak: worst single symbol (pass < 24% for 64QAM). Freq error: carrier offset from programmed frequency. Symbol rate: confirms correct FRC loaded. CRC: pass/fail on PBCH decode (if measuring DL reference signals).

FHGW DL chain — LowPHY, DFE, DAC, register map

FHGW DL processing chain:
eCPRI receive → BFP decompression (9-bit mantissa + 4-bit exponent → 16-bit IQ) → resource mapping → IFFT (1024/2048 point per BW) → cyclic prefix insertion → CFR (clip + filter, PAPR target 8 dB) → DPD (pre-distortion lookup + adaptation) → DFE (digital front-end: half-band filter, interpolation, frequency shift) → DAC interface (JESD204B) → DAC → analog path.
Key register map locations:
DPD coefficients: FHGW memory map 0x4000_0000 (DPD_COEF base). Read via: fhgw_read 0x40000000. CFR threshold: CFR_THRESH register. PAPR limit: CFR_CLIP_LEVEL. DPD enable: DPD_ENABLE_B1/B3/B41. DAC scale: DAC_SCALE per band → sets digital gain before DAC → directly affects output power. Incorrect DAC_SCALE causes TX power wrong by fixed offset independent of TX_GAIN calibration.
DPD observation path — how the feedback loop works:
A small portion of the PA output is tapped by the coupler and routed back to an observation ADC (ORX) on the FHGW. The ORX digitises this sample. DPD engine compares: ideal (DPD input) vs actual (ORX sample). Computes error and updates LUT (Look-Up Table) coefficients. Convergence: error < 1% = converged. Indicators: DPD_STATUS register bit, ACLR improvement from −30 dBc to < −45 dBc.

RFFE TX block diagram — B1/B3 three-band TX_A path

RFFE TX_A path structure (B1/B3/B41):
TX_A path handles Column A for all mid-band frequencies. Signal enters from FHGW DAC per band (B1 and B3 at different times or different IQ streams). Band selection switch routes to the correct PA driver and PA for each band. B1 PA and B3 PA are separate devices — different frequency response. B41 may share B1 PA hardware with band-specific matching network. RFFE board connects to midBRD via JESD204B high-speed differential interface.
Key RFFE control registers:
TX_GAIN per band per column: digital attenuator setting → sets output power. Written from tx_calibration_eeprom.json at boot. PA_BIAS per band: gate voltage setting → sets PA operating class and efficiency. PE44820DS: phase shifter per column → beamforming angle. RFFE_ENABLE per band: enables/disables RF path. All controlled via SPI bus from midBRD FPGA. CLI command: rffe_read/rffe_write for debug access.
Common RFFE faults in your work:
RFFE2 LB fault: Low-band RFFE (B8/B28) JTAG re-flash required when RFFE control firmware corrupted. Symptoms: B8/B28 fail to enable, fault code logged. Fix: 5-pin JTAG connector on RFFE2 board, flash via OpenOCD. Over-current fault: TX_OVERCURRENT register set to wrong value (default 0xFF = no protection). Correct per-band spec in register. See B3/B1 overcurrent discrepancy found by Dileep.

M11 PA Efficiency — how GaN PAs work, efficiency classes, Dynamic Vdd, what you can tune Advanced click to expand▾
PLAIN ENGLISH FIRSTPA efficiency in one sentence: The PA converts DC electricity into RF — but only 35% becomes useful signal; the rest becomes heat. Dynamic Vdd reduces this heat by lowering the supply voltage when the signal is quiet, just like dimming a light when you don't need full brightness.

PA efficiency — Dynamic Vdd, class AB, gate bias, power optimisation

PA efficiency classes — why Class AB:
Class A: always on, linear, efficiency ~30% max. Class B: on for half cycle, efficient ~78% max, but nonlinear crossover distortion. Class AB: compromise — on for slightly more than half cycle, efficiency ~35–45% with DPD linearisation. Class F: resonant load, theoretical ~90% but very narrowband. Your GaN PA operates Class AB — DPD handles the nonlinearity, and ~35% efficiency is acceptable for the power levels involved.
Dynamic Vdd — what it does and why it matters:
Dynamic Vdd (supply modulation) changes the PA drain voltage in proportion to the instantaneous signal envelope. For low-amplitude OFDM symbols, Vdd drops → less power wasted as heat. For high-amplitude peaks, Vdd rises → PA stays linear. This improves average efficiency from ~35% to ~50%+ for OFDM signals with their high PAPR. Your AAU has Dynamic Vdd implemented per column — the staircase supply voltage tracks the signal envelope in steps. The step size and timing are in the PA configuration registers.
Thermal management — why temperature monitoring matters:
GaN PA junction temperature limit: typically 150–200°C. At 20W output and 35% efficiency, each PA dissipates ~37W of heat. With 4 columns = 148W of heat generation inside the AAU enclosure. The thermal protection system monitors junction temperature via diode sensors and reduces power or shuts down if temp exceeds threshold. In your RCT: PA_PROTECTION fault typically triggers at 85–95°C junction. Check ambient temp and heatsink contact if PA protection fires repeatedly.
The efficiency problem
A macro PA can burn hundreds of watts. Drain efficiency = RF power out / DC power in. A PA is MOST efficient near saturation and LEAST efficient when backed off. But OFDM PAPR forces back-off. So at low traffic the PA sits deep in back-off, wasting power.
Dynamic Vdd — the core solution
Instead of one fixed drain voltage (Vdd) for all conditions, lower Vdd as traffic (RB occupancy) falls. Less Vdd at low load = efficiency peak moves to the backed-off operating point = less wasted power.

What you must re-tune when lowering Vdd
Lowering Vdd changes PA behaviour. You must re-tune: (1) CFR working point — pre-CFR gain register 0xb0290000: 0xD7 for occupancy > 50%, 0x128 for ≤ 50%. (2) Output power via DAC current. ACLR/EVM must stay within spec throughout the transition.
Transition order is critical: when load DROPS → lower Vdd AFTER occupancy has dropped (not before — you'd clip at the new Vdd). When load RISES → raise Vdd BEFORE occupancy increases (not after — the signal would clip at the old low Vdd).
Gate bias (Vgg) — second lever
The gate bias Vgg3_p (tested at −6.5 V datasheet, −5.5 V, −4.5 V) trades quiescent current for linearity. Adjusting Vgg adds further power savings especially when Vdd is already below nominal.
Safe PA bias sequencing (RENESAS)
GaN PA (RENESAS F8410/F84012) has drain rail (VDD) and gate rails (VGG1/2/3). Enabled by AND of TX_EN and MC_EN. Bias must follow the RENESAS sequence to avoid device damage. Even fully OFF: draws ~108 mA from VDD1 + ~1 mA leakage.

M13 RU Features & Operations — uSleep (power save), PA Protection, RSSI accuracy, IQ Playback Advanced click to expand▾
PLAIN ENGLISH FIRSTRU features in one sentence: uSleep turns the PA off when no users are connected (saves 70% power), PA protection shuts it down if it gets too hot, and IQ playback records what the RU received so you can replay it later for debugging.
1. uSleep (Micro-Sleep)

RU features — uSleep, PA protection, RSSI, IQ playback, DPD

uSleep — low power idle mode:
uSleep suspends RF chain when no UEs are scheduled. PA bias switches off → power consumption drops ~70%. Wakeup latency: <1 ms (fast enough for any LTE subframe). Trigger: scheduler indicates no DL allocations for N consecutive subframes. Config: USLEEP_THRESHOLD_N in RU config. During RCT: uSleep must be disabled or the EXM injection during "idle" subframes will not be received. Check: USLEEP_ENABLE = 0 in test mode.
PA protection — thermal, VSWR, over-current:
Thermal: TJ sensor monitors PA junction temp. Warning at 80°C, shutdown at 95°C. Recovery: auto when temp drops 10°C below threshold. VSWR: reflected power detector triggers if VSWR > 3.0 (10% reflected). Reduces power to protect PA from load mismatch. Over-current: PA drain current monitored. If > OVERCURRENT_THRESHOLD register: immediate PA disable. Default register 0xFF = no protection — set correct value per band per PA spec.
IQ playback — what it is and when to use:
IQ playback captures raw ADC samples (IQ data) from the RX chain and stores them in memory. Used to: replay a received signal for offline processing, debug PRACH detection algorithm without live UE, verify RX chain IQ integrity. CLI: iq_capture --band B1 --duration 10ms → saves IQ.bin. Replay with iq_playback command. Useful for debugging intermittent PRACH detection failures — capture the signal around the failure event and replay at leisure.
What uSleep is: PA (biggest power consumer, 40–200W) switches OFF during empty OFDM symbols. At low traffic, 60–80% of symbols may be empty → proportional power saving. Finer-grained than Dynamic Vdd (per-symbol vs per-subframe).
Failure: EVM spikes on symbol 0 after sleep but OK on symbol 1+ → PA bias slow to ramp. Check RENESAS gate bias sequencing registers.
2. Reduced Carrier Output Power
How it works: Lower the DAC current register or V ATT in RFFE. PA backs off → naturally more linear → ACLR/EVM improve. But efficiency drops (PA wastes more power as heat per useful watt out). Always wait 60s after power change for DPD to re-adapt before measuring ACLR.
